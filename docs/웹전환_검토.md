# 웹 교육 자료 전환 검토

검토일: 2026-11-15 · 대상: 이 저장소의 1,313개 차시 전체

## 결론

- **할 수 있고, 지금 구조가 유리하다.** 수업 내용이 `lessons/*.json` 에 장 종류(kind)와 그림 명세(figure)로 들어 있고 PPTX는 거기서 만든 결과물이다. 그래서 2,626개 PPTX를 "변환"할 필요가 없다. 같은 원본에서 **웹 출력을 하나 더 만들면** 된다.
- 그림 그리는 코드의 상당 부분이 이미 SVG·HTML로 있다(활동지·안내서 PDF가 HTML로 만들어진다). 슬라이드에 쓰인 좌표 그림 3,701개는 기존 `geo.js` 의 `toSvg` 로 **모두 오류 없이** 그려졌다(직접 실행해 확인).
- 웹으로 바꿀 때 가장 큰 이득은 화려한 애니메이션보다 **① 부모 화면과 아이 화면의 분리**, **② 아이가 직접 답하고 바로 확인**, **③ 조작하면 바뀌는 그림**(분수 막대, 수직선, 도형, 그래프) 순서다. ①·②는 지금 데이터로 대부분 된다. ③은 새로 써야 하므로 효과가 큰 차시부터 골라서 넣는다.
- PPTX → HTML 자동 변환 도구(LibreOffice 등)는 쓰지 않는다. 장의 의미(문제·정답·힌트·보충 연결)를 잃고, 조작 요소를 붙일 자리가 없다.

## 2. 핵심 판단: 출력을 하나 더 만든다

```
lessons/*.json ──┬─ tools/pptx      → 수업용·학생용 PPTX (지금)
                 ├─ tools/handouts  → 활동지·부모용 안내 PDF (지금, 유지)
                 └─ tools/web (신규) → 수업용·학생용 웹 페이지
```

### 다시 쓸 수 있는 것

| 이미 있는 것 | 웹에서 쓰임 |
|---|---|
| `geo.js` `KINDS`·`layout`·`toSvg` | 좌표 그림(도형·각·원·모눈·자·각도기) 3,701개를 SVG로. 순수 함수라 브라우저에서도 돈다 |
| `build_handouts.js` 의 `barSvg`·`clockSvg`·`numberlineSvg`·`gridSvg`·`arraySvg`·`pieSvg`·`tenframeSvg`·`bondSvg`·`tableHtml`·`eqHtml`·`fracHtml` | 초등 수학 그림 대부분. 지금은 mm 단위 인쇄용이라 크기·색만 화면용으로 바꾼다 |
| `scripts.js`, 단위 앞 줄바꿈 금지(`UNIT`), 밑줄 `⟦ ⟧` 처리 | 글자 처리 규칙을 그대로 |
| `style.js` 색·학년군별 글자 크기 | 화면 디자인 토큰 |
| `checks` 의 정확한 분수 계산(`check_lesson.py` 의 `exact`) | JS로 옮기면 아이가 입력한 답을 바로 채점 |
| 그림마다 있는 `alt` | 화면 읽기 프로그램용 대체 설명 |

### 새로 만들어야 하는 것

- 15개 장 종류의 HTML 배치(지금은 `kinds.js` 가 인치 좌표로 PPTX 도형을 놓는다).
- HTML 렌더러가 없는 그림: words, text, letters, flow, card, chip, timeline, shapes, blocks10, chart, vline, eqx. 대부분 글자 카드·상자라 CSS로 간단하다. shapes·blocks10만 SVG가 필요하다.
- `blocks` 장(37장)과 kind 없는 장(15장)은 인치 좌표를 쓴다. 고정 16:9 무대를 쓰면 그대로 옮길 수 있다(아래 5절).

## 3. 웹으로 얻는 것: 노력에 따라 세 단계

### 단계 0 — 원본을 고치지 않고 1,313개 차시 전체에 바로 되는 것

| 기능 | 근거 데이터 |
|---|---|
| 휴대폰·태블릿·TV 어디서나 브라우저로 열기 (PowerPoint 앱 불필요) | — |
| 절(도입·개념·연습·확인·정리·보충) 이동, 진행 막대, 키보드·스와이프 | `section` |
| 힌트를 처음엔 숨기고 "힌트 보기"로 열기 | `hint` 1,967장 |
| 선수 확인 장에서 "흔들리면 보충으로" 버튼 → 보충 장 → 원래 장으로 복귀 | `layout: support` 1,304장, 노트 `막히면` |
| 정답 공개를 부모가 누를 때만 (수업용) | `answers` 1,151장, 노트 `정답` |
| 앞 차시·다음 차시·앞 학년 차시로 연결되는 학습 지도 | `prerequisites`, `next`, `curriculum/units.json` |
| 이틀에 나누는 지점 표시 | `break_after` 1,313개 |
| 웹 글꼴로 기기와 상관없이 같은 모양 | 지금은 맑은 고딕(윈도 전용) 기준이라 맥·아이패드·LibreOffice에서 모양이 달라진다 |

### 단계 1 — 정답 데이터를 조금 정리하면 되는 것: 아이가 직접 답하고 바로 확인

| 대상 | 현재 데이터 | 할 일 |
|---|---|---|
| 고르기(choice) 514장 | 정답이 노트에 글로만 있다("가(4.68): …"). 정규식으로 450장(88%)은 정답 기호를 뽑을 수 있다 | 원본에 `answer` 필드를 추가. 나머지 64장은 손으로 |
| 빈칸 계산 문제 | `checks` 의 `blank` 14,169개가 식·정답·위치(`where: "S05 ①"`)를 가진다. 연습·확인 문제 17,965개 중 5,964개가 연결된다 | 위치 표기를 문제 번호와 확실히 묶기, JS 채점기 |
| 비교(compare) 1,577장 | "누가 맞을까?" — 정답은 노트에 글로 | `answer: "left" / "right"` 추가 |
| 정리 장의 ○/× , 다음 수업 복습 3문제 | `do`·`dont`·`review` | 뒤집기 카드, 다음 차시 첫 화면에 자동으로 |
| 기록표 | 안내서의 `record` 문장 | 화면에서 바로 체크해 기기에 저장(서버 없음) |

나머지 문제(설명하기, 쓰기, 말하기)는 지금처럼 부모가 판단한다. 자동 채점은 계산·고르기에만 쓴다.

### 단계 2 — 새로 써야 하는 것: 조작하면 바뀌는 그림

그림이 이미 **매개변수로 기술**되어 있으므로(`bars: {parts, shaded}`, `numberline: {min, max, jumps}`, `geo: {points…}`) 같은 명세에 "아이가 바꿀 수 있는 값"만 더하면 조작 그림이 된다.

| 그림 | 조작 예 | 사용 수 |
|---|---|---|
| bars · pie · grid | 칸을 더 나누어도 색칠한 양이 같은지 직접 쪼개 보기, 겹쳐 보기 | 92 · 21 · 134 |
| numberline | 뛰어 세기 화살표를 끌어 놓기, 음수 덧셈 이동 | 73 |
| array · tenframe · blocks10 | 점·수 모형을 끌어 묶기, 10 만들기, 받아올림 | 255 · 60 · 79 |
| clock · ruler · protractor | 바늘 돌리기, 물체를 자에 대기, 각도기 돌리기 | 101 · 22 · 7 |
| geo | 점을 끌면 길이·각·넓이가 바뀌는 동적 기하(합동, 원과 직선의 위치 관계 등) | 3,672 |
| 함수·그래프(고1 이차함수·유리함수 등) | 계수 슬라이더로 그래프 변화 보기 | 새 그림 종류 |
| 과학(낙하, 회로, 생태계, 중화) | 변인 조절 시뮬레이션 | 차시마다 따로 |

원본에는 `interactive` 같은 선택 필드를 더하고, 그 필드가 없는 차시는 지금처럼 정적인 그림으로 나온다. 모든 장을 조작형으로 만들 필요는 없다. **조작 자체가 배움인 개념 장**에만 넣는다.

## 4. 1:1 가정 학습에 맞춘 화면 구성

지금의 가장 큰 불편: 한 화면을 같이 보므로 노트(정답)가 아이에게 보일 수 있어서, 부모용 안내를 PDF로 따로 만든다(`home-tutoring.md`). 웹은 이것을 화면 구성으로 풀 수 있다.

| 방식 | 내용 | 서버 | 평가 |
|---|---|---|---|
| A. 한 화면 + 부모 버튼 | 아이 화면에서 정답·노트는 숨김. 부모가 길게 누르거나 단축키를 눌러 잠깐 본다 | 없음 | 가장 간단. 화면을 같이 보는 순간에는 아이도 본다 |
| B. 한 기기 두 창 | 노트북 + TV/모니터. 두 창이 같은 장을 따라간다(BroadcastChannel) | 없음 | 집에 모니터가 있으면 좋다 |
| C. 두 기기 동기화 | 부모 휴대폰이 리모컨 겸 노트, 아이 태블릿은 화면. QR로 짝짓기 | **필요**(실시간 중계) | 가장 자연스럽지만 서버 운영·개인정보 검토가 따른다 |
| D. 두 기기, 동기화 없음 | 부모 휴대폰에 "부모용 안내" 웹 페이지(장 번호별 발문·정답·막히면), 아이 화면은 따로 넘김 | 없음 | 지금 PDF의 웹판. 장 미리보기를 실제 화면으로 보여 줄 수 있다 |

**권장:** 서버 없이 되는 A + D로 시작하고, 실제로 써 보고 동기화가 꼭 필요하면 C를 더한다.

## 5. 지켜야 할 기존 원칙과 웹에서 달라지는 점

| 원칙 (현재 스킬 규칙) | 웹에서 |
|---|---|
| 학생용에 정답이 없어야 한다 | CSS로 숨기면 안 된다(중·고생은 소스 보기를 한다). **학생용 웹 빌드는 정답·노트·answers 장을 데이터에서 아예 뺀다.** 자동 채점이 필요한 학생용 문제는 정답 대신 해시를 넣거나, 학생용에서는 채점을 끄고 "부모에게 확인"으로 둔다 — 결정 필요 |
| 정답 공개는 별도 장으로, 애니메이션에 기대지 않는다 | 웹의 "공개" 상태는 버튼으로 분명하고 학생용에서는 없다. 규칙의 취지(믿을 수 있는 공개, 학생용 제거)는 지키고, 문구를 웹에 맞게 고친다 |
| 계산만 맞고 이유를 못 말하면 확인 완료가 아니다 | 자동 채점 뒤에 "어떻게 알았어?" 단계를 꼭 둔다. 맞힘 표시만으로 끝내지 않는다 |
| 글이 상자에 들어가야 한다(빌드가 어림 계산으로 검사) | **고정 16:9 무대**(1280×720 같은 논리 크기를 화면에 맞춰 확대·축소)를 쓰면 지금 글자 수 기준과 `blocks` 좌표를 그대로 쓴다. 넘침은 브라우저에서 실제로 재므로(`scrollHeight`) 지금보다 정확하다. 휴대폰 세로 화면은 부모용 안내에만 반응형으로 쓴다 |
| 사진·생성 삽화를 쓰지 않는다 | 유지. 조작 그림도 상태마다 수량이 맞는지 검사한다(예: 쪼갠 뒤에도 색칠 비율이 같은지) |
| 활동지는 종이 | 유지. 손으로 쓰는 연습은 종이가 낫다. 웹은 PPTX만 대신한다 |

## 6. 위험과 비용

- **렌더러 분량:** 장 종류 15개 + 그림 약 27종. 인쇄용 SVG가 있는 그림은 옮기기, 없는 것은 새로 쓰기. 가장 큰 덩어리는 장 배치(`kinds.js` 365줄 + `build_lesson.js` 620줄의 대응).
- **화면 검사:** 19,759장. 이미 있는 Playwright로 장마다 넘침 측정·스크린숏을 자동으로 한다. 눈 검사는 견본 차시와 바뀐 차시만.
- **글꼴:** 맑은 고딕은 웹에 실을 수 없다. Pretendard·Noto Sans KR(둘 다 OFL)을 쓰면 글자 폭이 달라지므로 학년군별 글자 수 기준을 한 번 다시 맞춘다.
- **공개 범위·호스팅:** 정적 파일이라 GitHub Pages·Cloudflare Pages 등에 올릴 수 있다. 저장소가 비공개면 Pages 요금제나 다른 호스팅을 정해야 한다. 인터넷 없이 쓰려면 차시 하나를 파일 하나(HTML에 SVG·글꼴 포함)로 만들 수 있다.
- **저장소 무게:** `dist/` 의 1.1 GB 바이너리가 git에 있다. 웹 출력은 글자 파일이라 훨씬 작지만, 생성물을 계속 커밋할지(또는 릴리스·배포로만 둘지) 이참에 정하는 것이 좋다.
- **스킬 문서:** `education-ppt` 스킬과 references가 PPT 기준이다. 웹 출력 규칙(조작 그림, 정답 데이터, 웹 검사)을 더해야 이후 제작·수정에서 일관된다.

## 7. 권장 진행 순서

1. **시제품 (차시 3개):** 학년·과목이 다른 3개를 골라 단계 0 + 단계 1 + 조작 그림 1개씩을 넣는다. 후보:
   - 초1 수학 `KR22-G01-MAT-NUM9-L01` (kind 견본, 십 칸·가르기)
   - 초5 수학 `KR22-G05-MAT-FRAC-EQUIV-L01` (좌표 블록 견본, 분수 막대 쪼개기)
   - 고1 수학 `KR22-G10-MAT-CIRCLELINE-L01` (geo, 원과 직선의 거리 조절)
   실제로 아이와 한 차시를 해 보고 화면 구성(4절)을 정한다.
2. **전체 정적 웹 출력:** 모든 장 종류·그림을 HTML/SVG로, 수업용·학생용 두 벌, 자동 넘침 검사. 1,313개 차시 전체에 단계 0 적용.
3. **정답 데이터 정리:** choice·compare에 `answer` 필드, `checks` 와 문제 번호 연결, 스키마·검사기 갱신 → 단계 1 전체 적용.
4. **조작 그림 라이브러리:** 초등 수학(분수 막대, 수직선, 십 칸·수 모형, 시계) → 중·고 수학(동적 기하, 그래프) → 과학 시뮬레이션 순으로, 효과가 큰 차시부터 `interactive` 를 붙인다.
5. PPTX 생성은 웹이 자리 잡을 때까지 함께 유지하고, 이후 그만둘지 정한다.

### 두 기기 + 파일 배포에서 확인할 것

- **태블릿에서 파일 열기**: 아이패드는 Safari로 내려받은 HTML 파일을 바로 열어 스크립트를 실행하기 어렵다. 안드로이드도 기기·브라우저에 따라 다르다. 가장 무난한 방법은 한 번 웹 주소로 열어 **홈 화면에 추가(PWA)** 하고, 그 뒤로는 인터넷 없이 쓰는 것이다. 이 방법은 나중에 공개 웹으로 바꿀 때도 그대로 이어진다.
- **두 기기 연결**: 인터넷 없이 두 기기를 실시간으로 잇는 것은 같은 와이파이 안에서 WebRTC로 가능하지만, 처음 연결할 때 QR 코드를 서로 비추는 단계가 필요하다(카메라 권한 → 보안 연결 필요 → PWA가 유리). 연결이 안 되면 **동기화 없이** 아이 화면에 장 번호를 크게 보이고 부모 휴대폰에서 같은 번호를 누르는 방식으로 물러선다.
- **기록 보존**: 파일로 연 페이지의 기록(실천표, 맞음·도움·아직)이 일주일 넘게 남는지 기기에서 시험한다. 지워질 수 있으면 종이 기록표를 기본으로 둔다.
- 기기: **아이패드와 안드로이드 둘 다** 쓴다(2026-11-15 결정). 시제품은 iOS Safari와 Android Chrome에서 모두 시험한다.

# 안드로이드·PC 앱 설계 메모

> **상태: 설계 메모, 시제품 없음.** 실제 기기로 확인한 것은 아직 없다. 시제품을 만들며 이 문서를 고친다.
> 원고를 쓸 때 지킬 규칙은 스킬의 `.claude/skills/education-ppt/references/app.md` 에 따로 있다(짧다). 이 문서는 앱을 만들 때 읽는다.

같은 원본(`lessons/*.json`)에서 PPTX와 함께 **안드로이드 앱**용 화면 자료를 만든다. 앱은 아이가 직접 조작하고 반복하는 화면이고, PPTX는 부모가 아이와 함께 보며 시범·비교·대화를 하는 화면이다. 두 형식의 내용과 목적은 달라도 된다. 앱에만 필요한 내용은 장·문항의 `app` 필드에 두고, PPTX 생성은 이 필드를 무시한다. **`app` 필드는 시제품으로 형식을 확정한 뒤에 원본에 넣는다**(지금은 어느 차시에도 없다).

화면은 웹 기술(HTML·SVG·JS)로 만들고 안드로이드 앱 껍데기에 넣는다. 개발 중에는 브라우저로 미리 본다. **앱은 안드로이드만 만들고, 스토어(Google Play)에 올리지 않고 직접 설치한다**(아래 ‘안드로이드 앱’). 나중에 **PC 앱(Rust)**을 만들 수 있으므로(아래 ‘PC 앱’), 학습 데이터는 앱과 떼어 두 앱이 같이 읽는 **자료 묶음**으로 만든다(아래 ‘자료 묶음’).

배경 검토: 브랜치 `claude/intelligent-volta-7k2ms5` 의 `docs/웹전환_검토.md`, `docs/초1_상세검토.md`(2026-11-15, 그 뒤 원본이 많이 바뀌었으므로 숫자는 다시 잰다. 그 문서의 PWA·아이패드 전제는 이 메모로 바뀌었다).

앱 화면의 글도 스킬의 다른 규칙을 그대로 따른다: 말투·문장 길이·등장인물(`tone-by-age.md`), 부모 노트와 1:1 진행(`home-tutoring.md`), 정답 자리와 시간(아래 ‘원본 규칙과 맞추기’).

## 정한 것

| 항목 | 내용 |
|---|---|
| 기기 | 안드로이드만. 기본은 두 기기: 부모 휴대폰(진행, 노트, 정답, 기록) + 아이 태블릿(화면, 조작, 답하기). **기기 한 대 모드도 반드시 둔다**(아래). 부모 휴대폰이 아이폰이면 앱을 쓸 수 없으므로, 아이 태블릿을 ‘기기 한 대’ 모드로 쓰고 부모는 부모용 안내 PDF를 본다 |
| 배포 | 앱 설치 파일(APK)을 직접 설치한다. 스토어에 올리지 않는다. 인터넷 없이 쓴다(자료를 처음 받을 때만 인터넷이나 파일 옮기기가 필요) |
| PC | 나중에 Rust로 PC 앱을 만들 수 있다. 같은 자료 묶음을 읽고, 화면 코드는 되도록 함께 쓴다(아래 ‘PC 앱’) |
| 학습 데이터 | 앱 코드와 뗀 자료 묶음(원본 JSON + 미디어 + 목록). 동영상·오디오·3D 모형을 넣을 수 있다. 실행 코드는 넣지 않는다 |
| 조작·실험 | 도형 옮기기·퍼즐·지구본·물질 섞기·물리 실험 등은 앱의 엔진 + 자료 묶음의 장면으로 만든다. 차시를 쓸 때 조작·실험으로 학습 효과를 높일 장을 검토해 원본에 남긴다(아래 ‘조작·실험 엔진’) |
| 두 기기 연결 | 안드로이드의 가까운 기기 연결(Nearby Connections)로 인터넷·공유기 없이 잇는다. 안 되면 장 번호 맞추기로 물러선다(아래) |
| 자동 채점 | 아이 화면에서 한다. 앱 자료에 정답이 들어 있어도 된다(학생용 PPTX의 정답 제거 규칙은 앱에 적용하지 않는다). 중·고생은 자료를 열어 볼 수 있다는 점을 알고 정한 것이다 |
| 그림 | 코드로 직접 그린 단순 아이콘을 쓸 수 있다(아래) |
| 제작 순서 | 초1부터 차례로. 묶음의 내용 보강(검토 보고서의 보강점)을 원본에 반영한 뒤 그 묶음부터 앱 화면으로 만든다 |

## 화면 구성

| 모드 | 내용 | 언제 |
|---|---|---|
| 두 기기 연결 | 부모 휴대폰이 장을 넘기면 아이 화면이 따라가고, 아이 답이 부모 휴대폰에 온다 | 연결에 성공했을 때 |
| 두 기기, 연결 없음 | 아이 화면에 장 번호를 크게 보이고 부모가 휴대폰에서 같은 번호를 누른다. 부모 판정은 부모 휴대폰에만 기록한다 | 연결이 안 되거나 끊겼을 때 |
| 기기 한 대 | 아이 화면에서 정답·노트·판정 단추를 숨기고, 부모만 여는 ‘부모 화면’(길게 누르기 + 숫자 잠금)으로 본다. 부모 화면이 열려 있는 동안 아이 화면은 가린다 | 안드로이드 기기가 한 대뿐일 때, 부모 휴대폰이 아이폰일 때 |

- 아이 화면에서 부모 화면·정답·설정으로 넘어가는 길은 잠금(‘부모 확인’) 없이 열리지 않게 한다. 설정, 기록 내보내기, 자료 받기, 권한 요청, 도움 기관 안내의 전화 걸기가 그 뒤에 있다.
- 아이 화면은 가로로 쓴다. 안드로이드 태블릿은 16:10이 많고 4:3도 있다. 16:9 무대를 넣었을 때 남는 칸 때문에 글자가 작아지므로, 학년군 글자 크기 기준을 **4:3과 16:10 화면에 넣었을 때** 기준으로 잰다.
- 아이가 여럿이면 기기 안에서 아이별로 기록을 나눈다(이름 대신 부모가 정한 별명).
- 다음 차시로 저절로 넘어가거나 끝없이 이어지는 화면을 두지 않는다. 한 회차가 끝나면 멈춘다.
- 연결이 끊기면 아이 화면을 멈추지 않는다. 지금 장을 그대로 두고 “부모님과 장 번호를 맞추세요”를 보인 뒤 ‘연결 없음’ 모드로 넘어간다.
- 아이가 수업 중에 다른 앱으로 나가지 않게 하려면 안드로이드의 ‘앱 고정’ 기능을 부모에게 안내한다(앱이 강제로 잠그지 않는다).

### 두 기기 연결

- Nearby Connections(Google Play 서비스에 들어 있음)는 블루투스·와이파이 직접 연결로 가까운 기기끼리 잇는다. 공유기·인터넷이 없어도 된다.
- 짝짓기: 부모 휴대폰이 ‘수업 열기’를 누르면 아이 태블릿에 찾은 기기가 뜨고, 두 화면에 같은 확인 숫자(4자리)가 보일 때 부모가 ‘맞음’을 누른다. 한 번 짝지은 기기는 다음부터 자동으로 다시 잇는다.
- 권한: 안드로이드 12 이상은 ‘근처 기기’ 권한 묶음(블루투스·근처 와이파이 기기)을 한 번 묻는다. 그보다 오래된 판은 블루투스 검색에 **위치 권한**을 요구한다. 위치를 쓰지 않는다는 표시(`neverForLocation`)를 하고, 묻기 전에 부모 화면에 까닭을 설명한다. 권한 요청은 ‘부모 확인’ 뒤에 둔다.
- Google Play 서비스가 없는 기기(일부 태블릿)에서는 Nearby Connections를 쓸 수 없다. 이때는 같은 와이파이 안의 일반 네트워크 연결(부모 휴대폰이 연결 지점을 열고 QR로 주소를 보임)로 물러서고, 그것도 안 되면 ‘연결 없음’ 모드로 간다.
- 연결은 두 기기 사이에서만 오가고 밖으로 나가지 않는다. 짝지은 기기만 받는다.
- 모든 수업은 ‘연결 없음’ 모드만으로 끝까지 할 수 있어야 한다. 실제 기기로 연결해 보기 전에는 ‘연결 모드가 된다’고 적지 않는다.

## 수업 단위: 하루와 이틀

- 원본의 `break_after` 가 하루 분량의 끝이다. `split_default: true` 인 차시(고등 대부분)는 앱에서도 **이틀 차시**로 연다: 첫날은 `break_after` 장까지, 둘째 날은 그다음 장부터.
- 둘째 날은 노트의 ‘둘째 날 시작 질문’을 첫 화면에 보이고, 첫날 내용을 2~3문제로 다시 꺼낸 뒤 이어 간다.
- 하루 중간에 멈추면 다음에 연 곳에서 이어 한다(어느 장·문항까지 했는지 기록).
- 노트의 ‘꼭 할 문제 / 시간이 되면’ 줄을 구조로 옮긴다(`app.priority: "must" | "optional"`). 부모가 ‘시간이 모자라요’를 누르면 남은 장에서 `must` 만 보인다. 문제를 지우지 않는다.
- 남은 시간 막대는 그날 분량(하루 약 20~30분) 기준으로 보인다. 끝나기 2~3분 전 “곧 끝나요”, 끝나면 “다 했어요 → 끄고 제자리에” 화면에서 멈춘다. 20분쯤 눈 쉬기를 안내한다.

## 문항의 `app` 필드

노트 문장에만 있던 정답·허용 답·오답 대응을 구조로 둔다. 연습·확인 장의 문항마다(고르기·견주기 장은 장에):

```json
"app": {
  "id": "q-borrow-13-5",
  "input": "numpad",
  "answer": "8", "accept": ["8", "여덟"],
  "steps": [ { "label": "중간 수", "answer": "10" } ],
  "wrong": [
    { "value": "12", "misconception": "M1", "feedback": "5개 뺐는데 1개만 줄었어요", "goto": "S04" }
  ],
  "priority": "must",
  "say": "열세 개에서 다섯 개를 빼면 몇 개일까요?",
  "lang": "ko"
}
```

| 필드 | 뜻 |
|---|---|
| `id` | 문항의 바뀌지 않는 이름. 장 번호(S05 ①)는 원본을 고치면 바뀌므로 기록·채점 연결에 쓰지 않는다. 한번 정하면 문항을 지울 때까지 바꾸지 않는다 |
| `input` | 아래 ‘입력 종류’ |
| `answer`, `accept` | 정답과 함께 맞음으로 볼 답. 같은 답으로 보는 규칙은 ‘답 맞추기’를 먼저 적용하고, 그 밖의 다른 꼴만 `accept` 에 적는다. 순서가 여럿 맞으면 `order` 의 허용 범위를 적는다(예: 처음과 끝만 고정) |
| `steps` | 중간 단계 칸(중간 수, 가르기 두 칸). 어느 단계에서 틀렸는지 구별한다 |
| `wrong` | 흔한 오답 → 원본 `misconceptions` 의 ID → 아이에게 보일 피드백(정답을 바로 말하지 않고 되묻기) → 돌아갈 장 |
| `priority` | `must`(꼭 할 문제) · `optional`(시간이 되면). 노트의 같은 줄과 맞춘다 |
| `say` | 기계 음성이 읽을 문장. 숫자·시각·단위는 읽는 말로 쓴다(“3시” → “세 시”, “13개” → “열세 개”, “8 − 3” → “팔 빼기 삼”). 고유어/한자어를 정해 쓴다 |
| `lang` | `say` 의 언어(`ko`, `en`). 영어 문장은 `en` 으로 따로 둔다 |

- 아이에게 보이는 글(`feedback`, 지시, 힌트)은 `tone-by-age.md` 를 따른다. 위 예처럼 해요체는 초등까지다. 중·고는 교과서식(설명 ‘~이다’, 물음 ‘~인가?’, 지시 ‘~하시오’)으로 쓴다.
- 말로 답하는 문항(두 가지로 읽기, 까닭 말하기, 소리 내어 읽기)은 `parent`: 아이 화면에는 문제만 보이고, 부모 화면에 ‘맞음 · 도움 · 아직’ 단추가 뜬다. 이 결과가 기록표가 된다.
- 정답이 없는 ‘나라면 어떻게 할까’ 고르기는 `none`: 고른 것을 부모 화면에 보내고, 부모가 ‘까닭 말함 / 도움’을 기록한다. 고른 뒤 표정·소리로 정답을 암시하지 않는다.
- 자동 채점 뒤에도 “어떻게 알았어?”를 묻는다. 계산이 맞아도 까닭을 말하지 못하면 개념 목표는 확인 완료가 아니다(`home-tutoring.md`).
- 자동 채점하는 문항은 정답이 하나로 정해지는지 먼저 확인한다. 여럿이면 `accept` 나 허용 범위를 적고, 정할 수 없으면 `parent` 로 둔다.

## 입력 종류

| `input` | 쓰는 곳 | 채점 |
|---|---|---|
| `numpad` | 수 하나(자연수·소수·음수) | 자동 |
| `expr` | 식·분수·근호·지수·부등식 구간·좌표·순서쌍(중·고 수학, 과학 계산) | 자동. 화면 수식 자판(분수 칸, √, ^, ≤ ≥, 괄호)을 쓰고, 값으로 같은지 비교한다(‘답 맞추기’) |
| `short` | 낱말·짧은 구(용어, 국어·사회 단답, 영어 낱말) | 자동. `accept` 를 넉넉히 적고, 정할 수 없으면 `parent` |
| `choice` · `multi` | 하나 고르기 · 모두 고르기 | 자동 |
| `tap` | 그림에서 누르기 | 자동 |
| `drag` | 끌어 넣기·분류. 끌기가 어려운 아이를 위해 ‘누르고 → 놓을 곳 누르기’도 늘 된다 | 자동 |
| `order` | 순서 맞추기 | 자동(허용 범위) |
| `compose` | 자모·숫자 카드 조립 | 자동 |
| `plot` | 좌표평면에 점·직선·그래프 찍기, 막대·꺾은선 그리기 | 자동(허용 오차를 적는다) |
| `code` | 파이썬 코드 쓰기·고치기(정보 차시) | 아래 ‘코드’ |
| `trace` | 따라 쓰기 | 부모 판정 |
| `write` | 문단 이상의 글(논증문, 비평문, 보고서, 영어 글쓰기) | 부모 판정. 원본의 기준표를 부모 화면에 보인다 |
| `parent` | 말로 답함 | 부모 판정 |
| `none` | 채점 안 함 | — |

- 수·식 입력은 기기 자판을 띄우지 않고 화면 자판을 쓴다(기기 자판이 문제를 가린다). 식 입력은 수식 입력 부품 하나(예: MathLive의 수식 칸·화면 자판)를 정해 쓰고, 학년마다 필요한 단추만 남긴다(초등: 숫자·분수 칸, 중·고: √, 지수, 부등호, 괄호).
- 한글 단답은 글자 조합이 끝난 뒤(조합 끝 이벤트) 채점한다. 조합 중인 글자로 채점하면 ‘가’를 치는 도중 ‘ㄱ’으로 틀림이 난다. 삼성 키보드와 Gboard는 조합 이벤트를 내는 방식이 달라 둘 다 시험한다.

### 답 맞추기 (자동 채점 전에 모든 답에 적용)

- 앞뒤 빈칸, 연속 빈칸, 전각/반각 문자는 무시한다. 한국어 단답의 띄어쓰기는 무시한다(띄어쓰기를 묻는 문항은 `exact: true`).
- 단위: ‘3 cm’, ‘3cm’, ‘3센티미터’를 같게 본다. 단위가 답의 일부인 문항(단위 고르기)은 `exact: true`.
- 수: 같은 값이면 같은 답으로 본다(1/2 = 0.5 = 2/4). 문항이 꼴을 묻는 경우(기약분수로, 소수로, 근호를 써서)는 `form` 에 적는다(`"form": "irreducible"`, `"decimal"`, `"radical"`). 반올림이 있으면 자리를 적는다.
- 식: ‘x = 3’과 ‘3’, ‘y = 2x + 1’과 ‘y = 1 + 2x’를 같게 본다. 구간·부등식은 같은 범위면 같다.
- 영어: 대소문자·끝 문장 부호는 무시한다. 철자를 묻는 문항은 `exact: true`.
- 계산 비교는 원본 `checks` 와 같은 계산기(정확한 분수 계산)를 JS로 옮겨 쓴다.

### 틀렸을 때

- 첫 번째 틀림: `wrong` 에 맞는 오답이면 그 피드백(되묻기), 아니면 일반 되묻기 + 힌트 열기.
- 두 번째 틀림: 원본 노트의 ‘막히면’ 안내를 따라 `goto` 장이나 보충 장으로 보낸다. 보충 뒤 원래 문항으로 돌아온다.
- 세 번째 틀림: 정답을 보여 주지 않고 부모 화면에 ‘도움 필요’를 보낸다. 기록은 ‘도움’이 된다.
- 고르기·견주기 장에서는 틀린 뒤 남은 보기를 차례로 눌러 맞히는 것을 막는다. 두 번째 시도부터는 고르기 전에 까닭을 말하게 하고(부모 판정) 그 뒤에 고른다.
- 틀림 소리·빨간 화면·점수 깎기를 쓰지 않는다. 맞음 표시도 짧게 한다.
- 어떤 경로로 끝나든 그 장을 떠나기 전에 아이가 **맞는 답과 까닭을 한 번은 확인**하게 한다(부모가 설명하거나 정답 장을 함께 본다). 답을 못 떠올린 채 확인 없이 넘어가는 반복 연습은 효과가 없거나 해롭다는 연구가 있다.
- 피드백은 바로 준다(나중에 모아서 주지 않는다). 설명형 피드백(왜 틀렸는지 되묻기)이 평균적으로 더 효과가 크지만 어린 학습자에게는 효과가 작다는 결과도 있으므로, 초1~2는 되묻기를 짧게 하고 시범(그림·조작으로 다시 보이기)으로 바로 잇는다.

## 원본 규칙과 맞추기

- **정답 자리:** 고르기·견주기의 맞는 쪽이 한쪽으로 몰리지 않게 한 원본 규칙(가/나, 왼쪽/오른쪽을 이웃 차시끼리 엇갈리게)을 앱도 지킨다. 앱에서 보기 순서를 섞지 않는다. 섞으면 부모 화면·노트의 ‘정답: 가’와 어긋난다. 섞고 싶으면 부모 화면에 지금 화면의 기호로 정답을 보인다.
- **자동 생성 연습:** 정답 자리와 정답 값이 고르게 퍼지게 만든다(같은 답이 연달아 나오지 않게, 고르기 정답 자리를 고르게).
- **시간·이틀 차시:** 위 ‘수업 단위’를 따른다.
- **말투:** 학년군별 말투를 앱의 모든 아이 화면 글에 적용한다. 따옴표 안의 말, 읽기 지문, 영어는 원본대로 둔다.
- **원본과 같이 고치기:** 원본을 고치면 앱 자료를 다시 만든다. 장 순서·번호가 바뀌면 `goto` 와 문항 `id` 연결을 다시 검사한다.

## 음성

| 구분 | 방법 | 예 |
|---|---|---|
| 기기 음성(TTS) | 안드로이드 음성 엔진(Google 음성 서비스, 삼성 TTS 등)으로 그 자리에서 읽는다. 파일이 필요 없다. `say` 와 `lang` 을 쓴다 | 낱말, 지시문, 이야기 읽어 주기, 받아쓰기 불러 주기, 수 읽기, 영어 문장 |
| 음성 파일 | 미리 만들어 함께 배포한다. 같은 목소리·같은 높이로 만든다 | 자모 낱소리([그] [끄] [크]), 받침 끝소리([윽] [은]…), 늘였다 줄이는 이어 읽기([그…아] → [가]), 예사·된·거센 세 짝, 문장 부호 억양 대비, 시 낭독, 목소리 비교 |
| 소리 효과 | 코드로 만든다 | 박(70·90·110 BPM), 손뼉·무릎, 효과음 |

- 기기마다 기본 음성 엔진과 설치된 언어가 다르다(삼성 기기는 삼성 TTS가 기본인 경우가 많다). 처음 열 때 한국어·영어 음성이 쓸 수 있는 상태인지 확인하고, 음성 데이터가 없으면 부모 화면에서 설치 화면으로 안내한다. 그래도 없으면 소리 단추 대신 “부모님이 읽어 주세요”를 보이고 부모 화면에 읽을 문장을 띄운다.
- 엔진이 오프라인 음성을 쓰는지 확인한다(인터넷 음성이면 오프라인에서 소리가 나지 않는다).
- 장이 바뀔 때 저절로 읽어 주지 않는다. 읽을 거리마다 소리 단추를 두어 아이가 누르게 한다(아이가 듣기를 조절한다).
- 읽는 빠르기를 부모가 바꿀 수 있게 한다(초1은 느리게 시작).
- 기계 음성에 자모 낱자(ㄱ, ㅏ)를 그대로 넣지 않는다(‘기역’으로 읽거나 소리를 내지 않는다). 낱소리는 음성 파일로 한다.
- 음성 파일은 처음 쓰기 전에 부모가 한 번 들어 확인하고, 마음에 들지 않으면 부모 휴대폰에서 직접 녹음해 바꿀 수 있게 한다. 녹음은 그 기기에만 저장한다(마이크 권한은 ‘부모 확인’ 뒤에서 묻는다).
- 소리로 구별하게 하는 문제를 만들지 않는 것: ㅐ/ㅔ, ㅚ/ㅙ/ㅞ, ㅒ/ㅖ(표준 발음에서도 구별이 약하다). 뜻으로 고르게 한다.
- 노트의 발음 표기 [ ]와 기계 음성이 다르게 읽지 않게, 쓴 대로 소리 나지 않는 낱말(참외[차뫼], 열쇠[열쐬])은 한글 단원의 예에서 피한다.
- 소리로만 전하는 내용에는 같은 내용의 글을 함께 보인다(소리를 못 듣는 상황).

## 그림(아이콘)

- 물건 하나·기호 하나를 나타내는 단순 아이콘을 SVG 코드로 직접 그린다. 생성형 이미지와 사진은 쓰지 않는다.
- 아이콘 안에 수량·글자를 넣지 않는다. 수량은 기존 그림(배열, 십 칸 틀, 수 모형)으로 나타낸다.
- 아이콘마다 이름을 붙이고, 같은 이름은 어디서나 같은 아이콘으로 쓴다. 사람 아이콘은 성별·나이가 한쪽으로 치우치지 않게 한다. 중·고 화면에는 어린 느낌의 캐릭터·동물 아이콘을 쓰지 않는다(`tone-by-age.md`).
- 글을 못 읽는 아이가 혼자 할 수 있게, 분류·고르기 문항의 낱말에는 아이콘과 소리 단추를 함께 둔다.

### 대체 설명 두 가지

- 그림마다 대체 설명을 **두 가지**로 둔다. `alt`(아이 화면용)는 정답을 드러내지 않는 설명(“시계 그림”, “상자 모양 물건 세 개”), `alt_full`(부모 화면·화면 읽기용)은 그림을 그대로 말하는 설명(“8시 30분을 가리키는 시계”).
- 화면 읽기(TalkBack)를 켠 아이에게 그림을 볼 수 없는 만큼의 정보를 줘야 하는 문항(시각 장애)은 `alt_full` 을 쓰되, 그 문항은 자동 채점에서 빼고 `parent` 로 둔다.

## 조작·실험 엔진

도형을 옮기고, 퍼즐을 풀고, 지구본을 돌리고, 물질을 섞고, 물체를 움직이는 활동을 만든다. **움직임을 계산하는 ‘엔진’은 앱(코드)에, 무엇을 보이고 무엇을 확인할지 적은 ‘장면’은 자료 묶음(데이터)에** 둔다. 차시마다 코드를 새로 짜지 않는다. 엔진을 늘릴 때만 앱을 새 판으로 낸다.

### 엔진 목록

| 엔진 | 하는 일 | 장면 데이터에 적는 것 | 예 |
|---|---|---|---|
| `move2d` 2D 조작 | 끌기·돌리기·뒤집기·자석처럼 맞춰지기, 칸에 넣기, 선 잇기 | 조각(모양·처음 자리·돌릴 수 있는 각), 목표(모양·칸), 허용 오차 | 평면도형의 이동, 칠교·펜토미노, 합동·대칭, 분류, 수 모형 |

| `model` 변화 모형 | 변인 조절 → 그래프로 변화 보기 | 식이나 규칙, 변인과 범위, 그래프 축 | 개체군, 생태계, 기후, 인구, 함수의 계수 |

- **물리 엔진:** Rapier처럼 Rust와 웹(JS·WASM)에서 같은 엔진을 쓸 수 있는 것을 고른다. 그러면 PC 앱(Rust)과 안드로이드 앱이 같은 결과를 낸다. 기기가 달라도 결과가 똑같아야 하면 ‘결정적(deterministic)’ 판을 쓰고, 장면 값에 sin·cos처럼 기기마다 조금씩 다른 계산 결과를 넣지 않는다(장면 데이터는 이미 계산된 수로 적는다).
- **물질 섞기는 물리 계산이 아니라 규칙표다.** 규칙표에 없는 조합은 “이 실험에서는 다루지 않는다”로 둔다(지어낸 결과를 보이지 않는다). 양을 다루는 반응(중화의 양, 몰)은 원본 `checks` 와 같은 계산기로 검산한다.
- **지도:** 지도 바탕은 Natural Earth(퍼블릭 도메인) 같은 사용 조건이 분명한 자료를 쓴다. Natural Earth는 실제 통제 기준으로 경계를 그리므로, 바다·섬·지역 이름과 경계 표시는 **우리 교과서 표기(동해, 독도 등)로 우리가 직접 넣는다.** 지구 텍스처(위성 사진 등)는 사용 조건을 확인한 뒤 쓴다.
- 엔진은 화면 읽기(TalkBack)와 ‘누르고 놓기’(끌기 대신)를 지원한다. 3D·물리가 느린 기기는 정지 그림과 미리 계산한 결과 표로 대신한다.

### 장면 데이터

장에 `app.interactive` 를 둔다.

```json
"interactive": {
  "engine": "physics",
  "scene": "scene-incline-cart",
  "goal": "B",
  "flow": ["predict", "run", "explain"],
  "vary": [ { "name": "빗면 기울기", "range": [10, 40], "step": 10, "unit": "°" } ],
  "measure": ["time", "distance"],
  "assumptions": "마찰과 공기 저항은 없다고 본다",
  "success": [ { "all_of": [ { "eq": ["prediction_recorded", true] }, { "gte": ["runs", 3] } ] } ],
  "fallback": "img-incline-results"
}
```

| 필드 | 뜻 |
|---|---|
| `engine`, `scene` | 엔진 이름과 자료 묶음 안의 장면 id(장면 파일: 물체·조각·물질·변인의 정의) |
| `goal` | 이 조작이 확인하는 목표(원본 `objectives` 의 A, B …) |
| `flow` | 활동 흐름(아래 ‘활동 흐름’) |
| `vary`, `measure` | 아이가 바꿀 수 있는 변인과 범위, 잴 수 있는 것 |
| `assumptions` | 모형이 단순화한 것. 화면에 그대로 보인다 |
| `success` | 성공 조건. **정해진 꼴만** 쓴다(아래) |
| `fallback` | 엔진을 쓸 수 없을 때 보일 정지 그림·결과 표 |

- **성공 조건의 꼴:** 같다(`eq`)·이상(`gte`)·이하(`lte`)·사이(`between`)·안에 있다(`inside`: 조각이 칸 안, 점이 영역 안)·겹친다(`overlap` 비율)·순서(`order`)·모두(`all_of`)·하나라도(`any_of`). 그 밖의 계산은 장면에서 할 수 없다. 자료 묶음에 실행 코드를 넣지 않는다는 원칙을 이렇게 지킨다.
- 장면 파일도 `manifest.json` 에 해시와 함께 들어가고, 앱은 장면을 형식 검사(스키마)한 뒤에만 연다.

### 활동 흐름

- **예상 → 해 보기 → 설명(POE):** 실험·시뮬레이션은 먼저 결과를 예상해 적게 하고(바꿀 수 없게 남긴다), 해 본 뒤 예상과 다른 점을 말하게 한다(부모 판정). 예상이 틀린 것은 틀림으로 치지 않는다.
- **구체 → 그림 → 기호(구체성 줄이기):** 수학 조작은 실물·조작 화면에서 시작해, 같은 화면에서 그림과 식이 함께 보이다가, 마지막에는 식만으로 풀게 한다. 조작 화면에 늘 식(기호)을 나란히 보여 둘을 잇는다.
- **안내가 있는 탐구:** 아무 안내 없이 마음대로 해 보게 하지 않는다. 한 번에 바꿀 변인은 하나(변인 통제)로 시작하고, 바꿀 수 있는 것을 화면 설계로 좁혀(묵시적 안내) 길을 잃지 않게 한다.
- **시범을 먼저:** 새 조작은 부모 시범(또는 짧은 시범 영상) → 함께 → 혼자 순서로 넘긴다.
- **결과 기록:** 측정값은 표에 자동으로 쌓이고, 아이가 그래프를 그리거나 규칙을 말하는 단계로 잇는다. 원본의 활동지(종이) 기록과 같은 꼴로 둔다.

- 지도: 바다·섬 이름과 경계 표시가 우리 교과서 표기와 같은지 본다.
- 조작 화면: 저사양 태블릿에서 끊기지 않는지, 끌기 없이 ‘누르고 놓기’만으로 끝까지 되는지, TalkBack으로 무엇이 어디에 있는지 들리는지 본다.

## 코드 (정보 차시)

- 파이썬 코드를 쓰는 차시(17개)는 앱 안에서 돌리는 파이썬(Pyodide 등)을 쓸 수 있다. 본체만 해도 수 MB이고 꾸러미를 더하면 수십 MB가 되어 앱 크기에 부담이 크다. 그래서:
  - 코드 실행이 없어도 수업이 끝까지 되게 만든다(코드와 출력 예측 → 원본에 적힌 실제 출력과 견주기).
  - 실행 기능은 기본 앱에 넣지 않고, 부모가 고를 때 받는 별도 ‘실행 꾸러미’로 둔다(학습 자료 묶음에는 실행 코드를 넣지 않는다, 아래 ‘자료 묶음’). 꾸러미는 표준 라이브러리 안에서만 쓰고, 정해 둔 판만 싣는다.
- 원본의 예시 코드와 그 출력은 앱에서 실제로 돌려 같은지 검사한다(원본 검토에서 python3로 확인한 값과 같아야 한다).
- 채점은 정해 둔 입력에 대한 출력 비교로 한다. 무한 반복을 막는 시간 제한을 둔다. 네트워크·파일 접근은 막는다.

## 자동으로 만드는 연습

- 연습량이 부족한 내용은 앱이 문제를 만들어 반복한다. 틀린 문제는 간격을 두고 다시 낸다(같은 날 몰아서 하기보다 날을 나누어 다시 내는 것이 효과가 크다). 통과 기준(예: 연속 10문제 중 9개)을 정한다.
- 시간 기준(한 문제 5초 안)은 **정확하게 풀게 된 뒤에만** 쓴다. 시간은 아이에게 보이지 않게 재고(초시계 화면 없음), 점수나 순위로 보이지 않는다. 시간 제한 연습이 불안을 키운다는 주장과 그렇지 않다는 연구가 엇갈리므로, 부모가 끌 수 있게 한다.
- 복습 연습은 이미 배운 여러 유형을 섞어 낸다(섞어 풀기). 유형을 고르는 판단 자체가 배움인 중·고 수학에서 특히 쓴다. 초등에서 섞어 풀기의 근거는 아직 적으므로, 초등은 한 유형을 충분히 익힌 뒤에 섞는다.
- 초1 수학 사실 줄기: 10의 짝 → 10 − □ → 10 + 몇 → 받아올림 36개 → 받아내림 36개.
- 생성기는 원본의 `checks` 와 같은 계산기로 정답을 만든다. 만든 문제의 그림 수량이 정답과 맞는지 검사한다.
- 만든 문제는 그 차시의 범위(`boundary`) 안에 머문다. 아직 안 배운 수의 범위·꼴·낱말을 쓰지 않는다.
- 생성은 고정값(seed)으로 다시 만들 수 있게 하고, 검사에서 seed 몇 개로 만든 문제를 모두 검산한다.

## 자료 묶음 (형식·미디어·판)

학습 데이터는 앱 코드와 떼어 **자료 묶음**으로 만든다. 안드로이드 앱과 PC 앱이 같은 묶음을 읽는다. 원본(`lessons/*.json`)에서 도구로 만들고, 손으로 고치지 않는다.

### 묶음의 모양

```
g01-mat-v3/                 ← 학년·과목 단위, 판 번호
  manifest.json             ← 묶음 판, 차시 목록, 파일마다 해시·크기·형식·길이·출처(저작권)
  lessons/<ID>.json         ← 원본에서 만든 화면 데이터(app 필드 포함)
  media/audio/…             ← 자모 낱소리, 시 낭독, 영어 듣기
  media/video/…             ← 시범 영상, 자막(.vtt), 첫 화면 그림(poster)
  media/3d/…                ← 3D 모형(.glb)
  media/img/…               ← 그림(SVG 등)
  signature                 ← 묶음 서명
```

- 차시 데이터는 파일 경로를 직접 쓰지 않고 **미디어 id** 로 부른다. 파일 위치·형식·여러 화질은 `manifest.json` 이 알려 준다. 형식을 바꾸거나 화질을 더해도 차시 원본은 그대로다.

```json
"media": [
  { "id": "v-clock-minute-hand", "type": "video", "poster": "img-clock-poster",
    "captions": "vtt-clock-minute-hand", "alt": "긴바늘이 한 바퀴 도는 영상", "role": "demo" },
  { "id": "m3d-cylinder", "type": "model3d", "alt": "둥근기둥 모양 3D 모형", "role": "explore" }
]
```

- `manifest.json` 의 파일 항목: `id`, `path`, `type`(audio·video·model3d·image·captions), `mime`, `bytes`, `sha256`, 길이(초)·해상도·꼭짓점 수 같은 크기 정보, `variants`(같은 미디어의 다른 형식·화질), `source`(직접 만듦 / 출처와 사용 조건).
- 묶음은 ‘기본’(차시 데이터·그림·짧은 소리)과 ‘미디어’(영상·3D·긴 소리)로 나누어, 부모가 학년·과목별로 골라 받는다. 기본 묶음만으로도 모든 차시를 끝까지 할 수 있어야 한다(영상·3D가 없으면 정지 그림과 글로 대신한다).

### 미디어 형식

두 앱(안드로이드 웹뷰, PC 앱)이 모두 읽을 수 있고 되도록 사용료 부담이 없는 형식을 쓴다.

| 종류 | 기본 형식 | 함께 둘 수 있는 형식 | 메모 |
|---|---|---|---|
| 오디오 | Opus(.ogg 또는 .webm) | AAC(.m4a) | 짧은 소리가 많아 작은 형식을 쓴다. 같은 목소리·같은 크기(음량 맞춤)로 만든다 |
| 동영상 | MP4(H.264 + AAC) | WebM(VP9 또는 AV1 + Opus) | H.264는 특허 코덱이라 리눅스 등 일부 환경에서 재생 꾸러미가 없을 수 있다. 그런 환경을 쓰면 WebM 판을 함께 둔다 |
| 자막 | WebVTT(.vtt) | — | 영상·긴 소리에는 반드시 둔다 |
| 3D 모형 | glTF 2.0 이진 파일(.glb) | — | 크로노스 그룹의 열린 표준. 웹(three.js 등)과 Rust 모두 읽는다 |
| 그림 | SVG | WebP, PNG | 지금 생성 도구가 SVG를 그린다 |

- **크기 상한**(처음 값, 써 보며 고친다): 영상은 720p·한 편 2분 안팎, 소리는 시 낭독 한 편 2분 안, 3D 모형은 한 개 2 MB 안. 넘으면 나누거나 줄인다.
- **3D 압축:** glTF의 메시 압축(Draco, meshopt)과 텍스처 압축(KTX2)은 읽는 쪽이 지원해야 한다. Rust 공식 `gltf` 크레이트는 이 압축 확장을 지원하지 않는 것으로 확인되었다(다른 크레이트·포크가 일부 지원). 그래서 기본은 **압축 확장 없이** 꼭짓점 수를 줄인 단순한 모형으로 만들고, 압축이 꼭 필요하면 두 앱의 읽는 쪽이 모두 지원하는지 확인한 뒤 쓴다.
- 3D 모형은 단위(미터)·원점·앞쪽 방향을 정해 두고 모든 모형이 지킨다(돌려 보기·크기 비교가 어긋나지 않게).

### 미디어를 쓰는 원칙

- **직접 만든 것이 기본이다.** 지금 규칙(사진과 생성형 이미지는 쓰지 않는다)을 영상·3D에도 적용한다: 시범 영상은 화면 녹화·그림 움직임·손 시범(얼굴 없이)으로 만들고, 실제 아이의 얼굴·목소리를 넣지 않는다. 생성형 영상·음성은 쓰지 않는다. 외부 자료(CC0·CC-BY 3D 모형, 공공 기관 영상 등)를 쓰면 출처와 사용 조건을 `manifest.json` 의 `source` 에 적고, 조건을 확인하지 못한 것은 넣지 않는다.
- **영상만으로 가르치지 않는다.** 영상은 시범·관찰(실험 장면, 시곗바늘의 움직임 등)에 쓰고, 그다음은 아이가 직접 조작하거나 답한다. 영상은 장 하나에 하나, 짧게.
- **재생:** 저절로 재생하지 않고 아이가 눌러야 재생한다. 끝나면 다음 영상으로 넘어가지 않는다. 다시 보기·멈추기·자막 켜기를 늘 둔다. 소리와 영상의 내용은 자막·글로도 볼 수 있게 한다.
- **3D:** 돌려 보기·크게 보기·단면 보기 같은 조작은 앱의 ‘3D 보기’ 부품이 맡고, 자료 묶음에는 모형과 보기 설정(처음 각도, 돌릴 수 있는 축, 표시할 이름표)만 넣는다. 화면 읽기를 위해 `alt` 를 둔다. 3D를 볼 수 없는 기기(성능 부족)는 정지 그림으로 대신한다.
- **과학 시뮬레이션처럼 움직임을 계산하는 것**은 앱 안의 부품(코드)이 맡고, 자료 묶음에는 매개변수만 넣는다.

### 안전: 실행 코드 없음, 서명

- 자료 묶음에는 실행 코드(JS, WASM, 스크립트)를 넣지 않는다. 미디어 파일도 데이터지만 디코더가 읽으므로 **출처 확인**이 중요하다:
  - 묶음 전체를 우리 키로 서명하고(예: Ed25519), 앱은 서명과 파일마다 해시를 확인한 뒤에만 연다. 서명이 맞지 않거나 해시가 다르면 묶음을 쓰지 않는다.
  - 서명 키는 앱 서명 키와 따로 두고, 마찬가지로 두 곳 이상에 안전하게 보관한다(저장소에 넣지 않는다).
- 예외: 정보 차시의 파이썬 실행(Pyodide 등)은 묶음이 아니라 앱(또는 앱이 받는 별도 실행 꾸러미)에 넣고, 정해 둔 판만 싣는다.

### 판과 기록

- 묶음마다 판 번호(원본 내용의 해시)를 붙인다. 원본을 고치면 앱을 다시 설치하지 않고 자료 묶음만 바꾼다. 부모 화면에서 ‘자료 받기’(정해 둔 배포 주소 한 곳) 또는 ‘파일에서 가져오기’(묶음 파일을 기기에 옮겨 넣기)로 바꾼다. 수업 중에는 바꾸지 않는다(다음에 열 때 바뀜). 받다가 끊기면 이전 판을 그대로 쓴다.
- 미디어 파일은 해시가 같으면 다시 받지 않는다(차시 글만 고친 판은 작게 받는다).
- 화면 동작이 바뀌면 앱을 새 판으로 설치한다. 묶음 형식에도 판 번호(`format_version`)를 두고, 앱이 읽을 수 없는 새 형식이면 “앱을 업데이트하세요”를 보인다.
- 기록은 문항 `id` 와 차시 판으로 남긴다. 판이 바뀌어도 같은 `id` 의 기록은 이어지고, 없어진 문항의 기록은 ‘지난 판’으로 남긴다.

## 안드로이드 앱 (스토어 없이 직접 설치)

### 만드는 순서

1. 정답 데이터(`app` 필드)를 원본에 정리한다.
2. 화면을 웹 기술로 만들어 브라우저에서 시제품을 보고, 실제 수업으로 써 본다.
3. 같은 화면 코드를 앱 껍데기(Capacitor 등, 웹 화면을 앱 안에서 띄우는 방식)에 넣어 안드로이드 앱으로 만든다. 처음부터 안드로이드 전용 코드(Kotlin 등)로 화면을 따로 짜지 않는다.
4. 앱 기능(저장, 기기 연결, 음성, 카메라, 파일)은 한 곳(바꿔 끼우는 층)에 모은다. 화면 코드는 그 층을 부르고, 브라우저 미리보기에서는 같은 층의 가짜 판을 쓴다.

### 설치와 업데이트

- 앱 설치 파일(APK)을 기기에 옮겨 설치한다. 기기 설정에서 그 경로(파일 앱 등)의 ‘알 수 없는 앱 설치’를 허용해야 하고, Play 프로텍트가 경고를 띄울 수 있다. 설치 안내를 부모용 문서로 만든다.
- **서명 키를 잃어버리지 않는다.** 앱은 처음 서명한 키로만 업데이트된다. 키를 잃으면 앱을 지우고 다시 깔아야 하고, 그때 기기 안의 기록이 지워진다. 키와 비밀번호를 두 곳 이상에 안전하게 보관한다(저장소에 넣지 않는다).
- 업데이트는 같은 키로 서명한 새 APK를 덮어 설치한다(기록이 남는다). 버전 번호를 올린다.
- **안드로이드 개발자 인증:** Google은 인증된(구글 인증) 안드로이드 기기에서 앱을 설치하려면, 스토어 밖에서 받은 앱도 개발자 인증을 거치게 바꾸고 있다. 2026년 9월 일부 나라부터 시작해 2027년 이후 전 세계로 넓힌다고 밝혔다. 가족 몇 대에만 쓰는 경우 무료 ‘제한 배포’ 계정(학생·취미용, 기기 20대까지, 신분증·등록비 없음)이 맞는다. 개발 중에는 ADB로 설치할 수 있다. 한국에 적용되는 시기와 조건은 설치 전에 Google 안내를 다시 확인한다.
- 지원할 가장 오래된 안드로이드 판(minSdk)과 시험할 기기(집에 있는 휴대폰·태블릿)를 정한다. 그 범위의 실제 기기로 검사한다.

### 스토어에 올리지 않아도 지키는 것

- 스토어 심사는 없지만, 아이용 앱에 대한 스토어 규칙(Google Play 가족 정책, App Store Kids 분류)이 요구하는 것을 그대로 지킨다: 광고·외부 분석 도구 없음, 기기 식별자·위치를 보내지 않음, 바깥 링크·결제·권한 요청은 부모 확인 뒤에만.
- 권한은 필요한 것만 묻는다: 근처 기기(연결), 카메라(QR, 물러서는 연결에만), 마이크(부모 녹음). 인터넷 권한은 자료 받기에만 쓴다. 위치·연락처·저장소 전체 접근은 묻지 않는다(파일은 시스템 파일 고르기 창으로 주고받는다).
- 앱 안에 무엇을 저장하고 무엇을 보내지 않는지 적은 짧은 안내(개인정보 안내)를 부모 화면에 둔다.

### 앱 검사(‘검사’에 더해)

- 두 기기 연결: 안드로이드 휴대폰 + 태블릿을 **공유기 없이** 잇는다. 블루투스를 껐다 켰을 때, 한 기기가 잠들었다 깼을 때 다시 붙는지 본다. Google Play 서비스가 없는 기기에서 와이파이 연결·‘연결 없음’으로 물러서는지 본다. 안드로이드 11 이하 기기에서 위치 권한 안내가 나오는지 본다.
- 설치·업데이트: 새 APK를 덮어 설치한 뒤 기록이 남는지, 다른 키로 서명한 APK가 설치되지 않는지 본다.
- 자동 백업: 앱 기록이 Google 드라이브 백업에 들어가지 않는지 본다(`adb shell bmgr` 등으로 확인).
- 자료 묶음: 새 판을 받은 뒤 기록이 이어지는지, 받다가 끊겼을 때 이전 판으로 그대로 쓰는지 본다. ‘파일에서 가져오기’로도 바뀌는지 본다.
- 개인정보: 앱이 보내는 네트워크 요청을 기록해, 자료 받기 외에 밖으로 나가는 요청이 없는지 확인한다.
- 부모 확인을 거치지 않고 바깥 링크·권한 요청·설정·전화 걸기에 닿는 길이 없는지 본다.

## PC 앱 (Rust, 나중에)

- 같은 자료 묶음을 읽는다. 자료 묶음 형식은 안드로이드 앱과 PC 앱이 함께 쓰는 약속이므로, 형식을 바꿀 때는 두 앱을 함께 생각한다(`format_version`).
- **화면은 되도록 함께 쓴다.** Rust 앱이 웹뷰를 쓰는 방식(Tauri 등)이면 안드로이드 앱과 같은 화면 코드를 그대로 쓰고, Rust는 저장·파일·연결·서명 확인을 맡는다(‘바꿔 끼우는 층’의 PC 판). Rust 고유 화면(egui, bevy 등)으로 그리면 화면을 두 벌 만들고 두 벌을 같게 검사해야 하므로, 처음에는 웹뷰 방식을 권한다.
- **미디어 재생은 운영 체제의 웹뷰가 맡는다**(웹뷰 방식일 때): Windows는 WebView2, macOS는 WKWebView, 리눅스는 WebKitGTK다. 리눅스 WebKitGTK는 설치된 GStreamer 꾸러미에 따라 H.264 영상이 재생되지 않을 수 있다(꾸러미를 깔아야 재생된 사례가 보고됨). 리눅스를 지원하면 WebM·Opus 판을 함께 둔다. 실제 기기에서 확인하기 전에는 ‘재생된다’고 적지 않는다.
- **3D:** 웹뷰 방식이면 화면 코드의 3D 보기(three.js 등)를 그대로 쓴다. Rust 고유 화면이면 `gltf` 크레이트 등으로 읽되, 위 ‘3D 압축’ 제약을 따른다.
- **두 기기 연결:** PC에는 안드로이드의 Nearby Connections가 없다. PC와 안드로이드를 이을 때는 같은 와이파이 안의 일반 네트워크 연결(PC나 휴대폰이 연결 지점을 열고 QR로 주소를 보임)을 쓴다. PC 방화벽이 연결을 막을 수 있으므로 처음 연결 때 안내한다. 안 되면 ‘연결 없음’ 모드로 간다.
- **PC의 쓰임:** 큰 화면은 아이 화면으로 쓰고(부모는 휴대폰), 또는 부모가 자료 묶음을 받아 안드로이드 기기로 옮기는 곳으로 쓴다. 키보드가 있으므로 중·고의 긴 글(`write`)·코드(`code`) 입력은 PC가 편하다.
- **기록과 개인 정보:** 안드로이드 앱과 같은 원칙을 지킨다(기기 안에만 저장, 외부 분석 도구 없음, 기록 내보내기·가져오기). PC 사용자 계정 폴더 안의 앱 전용 위치에 저장하고, 클라우드 동기화 폴더(OneDrive 등)에 저장하지 않는다. 안드로이드 기록과 PC 기록은 ‘기록 내보내기·가져오기’ 파일로 옮긴다(같은 형식).
- **배포:** 스토어 없이 설치 파일로 나눈다. Windows는 서명하지 않은 설치 파일에 SmartScreen 경고가, macOS는 공증하지 않은 앱에 Gatekeeper 경고가 뜬다. 가족 안에서만 쓰면 설치 안내로 넘기고, 넓게 나누게 되면 코드 서명을 검토한다.
- **검사:** 같은 자료 묶음으로 안드로이드와 PC에서 같은 차시를 열어 화면·채점·기록이 같은지 견준다.

## 밖에 공개하게 되면 (지금은 계획 없음)

- 앱이나 자료를 가족 밖에 나누게 되면 저작권을 다시 확인한다. 저작권법의 수업 목적 이용(제25조)은 학교·교육기관의 수업에 대한 것이고, 가정 안 복제(제30조 사적 이용)도 남에게 나누는 것까지 덮지 않는다. 나눌 자료에는 **보호기간이 끝난 작품(저작자 사망 다음 해부터 70년)이거나 허락을 받은 것, 직접 지은 글**만 싣는다. 보호기간이 끝난 작품은 한국저작권위원회 ‘공유마당’에서 확인한다.
- 지금 국어 지문은 보호기간이 끝난 작품(현진건 「운수 좋은 날」, 김유정 「동백꽃」, 김소월 「진달래꽃」, 한용운 「님의 침묵」, 이효석 「낙엽을 태우면서」 등)과 지어낸 글이다. 새 지문을 넣을 때마다 확인한다.
- 글꼴은 함께 실을 수 있는 것만 쓴다. Pretendard와 Noto Sans KR은 SIL Open Font License라 앱에 함께 실을 수 있다. 쓰는 글자만 남겨(subset) 크기를 줄인다.
- 기록을 서버로 모으는 기능을 넣는다면 개인정보 보호법 제22조의2(만 14세 미만)와 아동용 고지(쉬운 말)를 먼저 검토한다.

## 검사

- 장마다 고정 16:9 무대에서 글 넘침을 실제로 잰다(앱과 같은 화면 엔진).
- `app` 필드: 정답이 원본 `checks`·노트와 같은지, `wrong` 의 오개념 ID가 원본에 있는지, `goto` 장이 있는지, `id` 가 차시 안에서 겹치지 않는지, `priority` 가 노트의 ‘꼭 할 문제’ 줄과 맞는지.
- 답 맞추기: 문항마다 `answer` 와 `accept` 가 실제로 맞음으로 판정되는지, 흔한 오답이 맞음으로 판정되지 않는지 자동으로 돌려 본다.
- 아이 화면에 정답이 미리 보이지 않는지(그림 `alt`, 캡션, 칸 수, 보기 순서).
- 정답 자리: 차시와 이웃 차시의 고르기·견주기 정답 분포를 센다.
- 말투: 아이 화면 글이 학년군 말투를 지키는지(원본 검사와 같은 방식).
- 접근성: 자동 검사 도구(axe 등)와 대비 검사를 돌리고, TalkBack으로 한 차시를 해 본다.
- 오프라인: 비행기 모드에서 처음부터 끝까지 한 차시를 한다(소리·그림·코드 실행 포함).
- 기록 보존: 기록을 남기고 일주일 뒤, 기기를 다시 켠 뒤, 앱을 업데이트한 뒤에도 남아 있는지 본다. 판을 바꾼 뒤에도 이어지는지 본다.
- 성능: 오래된 보급형 안드로이드 태블릿에서 장 넘김·조작이 늦지 않은지 본다.
- 화면 비율: 16:9 무대를 4:3·16:10 태블릿에 넣었을 때 학년군 글자 크기 기준을 지키는지 잰다.
- 한글 입력: 삼성 키보드와 Gboard로 단답을 쳐서 조합 중에 틀림이 나지 않는지 본다.
- 소리: 한국어 음성이 없는 상태, 다른 엔진(삼성 TTS·Google)으로 바꾼 상태에서 읽기와 ‘부모님이 읽어 주세요’ 물러서기가 되는지 본다.
- 자료 묶음: `manifest.json` 의 모든 파일이 있고 해시·크기가 맞는지, 차시 데이터가 부르는 미디어 id가 모두 있는지, 서명이 맞는지, 실행 코드가 들어 있지 않은지 자동으로 검사한다. 일부러 파일 하나를 바꾼 묶음을 앱이 거부하는지 본다.
- 미디어: 영상·소리마다 길이·해상도·크기 상한, 자막이 있는지, 음량이 고른지 잰다. 3D 모형은 꼭짓점 수·크기·단위·원점을 검사하고, 쓰지 않기로 한 압축 확장이 들어 있지 않은지 본다. 기본 묶음만 받은 상태에서 모든 차시가 끝까지 되는지(정지 그림으로 대신하는지) 본다.
- 시험한 기기(제조사·모델·안드로이드 판, PC 운영 체제)를 적는다. 확인하지 못한 기기는 통과로 적지 않는다.

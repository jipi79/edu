# education-ppt

한 차시 = 한 PPT 파일. 수업 내용은 `lessons/` 의 JSON 원본에 두고, PPTX·PDF는 그 원본에서 만든다.
PPTX를 직접 고치지 않는다. 원본을 고치고 다시 생성한다.

## 기본값 (사용자가 다르게 말하지 않으면)

- 사용 방식 `home-1to1`: 부모가 집에서 아이 한 명을 가르친다. 아이는 학교 학습이 부족하다.
  → `references/home-tutoring.md` 를 반드시 읽는다.
- 교육과정: 2022 개정 / 권장 학년 배치 v1 (`curriculum/`). 화면 16:9, 한국어, 약 40분.
- 산출물 네 가지: 수업용 PPTX(노트 포함), 학생용 PPTX(정답 장·노트 제거), 활동지 PDF, 부모용 진행 안내 PDF.

필수 입력은 학년(또는 수준)·계통·주제(또는 모듈 ID)다. 모르는 값은 추정해 원본에 적고, 대상 학년이나 범위가 충돌해 결과가 달라질 때만 묻는다.

## 모드

| 모드 | 요청 예 | 완료 결과 |
|---|---|---|
| 계획 | 초5 수학 전체를 차시로 나눠줘 | 모듈 목록·순서·목표·선수 관계 (원본 status: 계획) |
| 제작 | 크기가 같은 분수 수업 만들어줘 | 원본 + PPTX 2벌 + PDF 2개 + 목차 갱신 |
| 검토 | 이 수업의 목표와 난도를 봐줘 | 장 번호가 붙은 수정 사항 |
| 수정 | 그림을 쉽게 바꾸고 연습을 늘려줘 | 고친 원본, 다시 만든 파일, 변경 기록 |
| 묶음 | 분수의 성질 단원 전체 | 차시별 파일, 단원 목차, 완료·보류 현황 |

## 절차

1. **범위**: 요청과 `plans/초등_차시계획.md`(초등 전체 414차시 계획과 제작 현황), `lessons/INDEX.md`를 읽는다. 공식 기준과 권장 배치의 구분은 `references/curriculum.md`.
2. **분할·계획**: 초등은 `plans/elementary/G0N.txt` 에 차시가 이미 나뉘어 있다. 차시를 더하거나 고칠 때는 이 파일을 고치고 `python3 -I tools/plan/build_plan.py` 로 검사한다(ID·단원·선수 차시·순환). 중·고는 같은 형식으로 새 계획 파일을 만든다.
3. **뼈대**: `python3 -I tools/plan/new_lesson.py <수업 ID>` 가 계획에서 원본 뼈대를 만든다(메타데이터·교육과정 연결·선수 차시).
4. **목표**: 목표마다 확인 방법(학습 증거)과 성공 기준을 먼저 쓴다. `references/lesson-design.md`.
5. **원고**: 장·활동지를 쓴다. 장 종류와 그림, 글의 양, 정답 검산은 `references/authoring.md`, 과목별 규칙은 `references/subjects/` 의 해당 파일만 읽는다. 내용 JSON을 따로 쓰고 `python3 -I tools/plan/fill_lesson.py <뼈대> <내용>` 으로 합쳐도 된다.
6. **검사·제작**: `tools/build_one.sh <원본>` (원고 검사 → PPTX 2벌 → 활동지·안내 PDF → 출력 검사). 글이 넘치거나 검사가 실패하면 원고를 고쳐 다시 돌린다.
7. **화면 검증**: `python3 -I tools/preview.py <원본> <임시 폴더>` 로 모든 장의 미리보기를 만들어 직접 본다(넘침·겹침·잘림·숫자와 단위가 갈라진 줄바꿈·그림과 설명의 불일치). `references/visuals-and-qa.md`.
8. **등록**: 원본 `status` 를 "제작 완료"로 두고 `tools/build.sh <원본…>` 으로 목차(`lessons/INDEX.md`)와 계획 현황을 갱신한 뒤 커밋한다. 검사하지 못한 항목은 통과로 적지 않는다.

## 완료 기준

- `check_lesson.py`, `check_output.py` 가 통과하고, 렌더링한 모든 장과 PDF를 눈으로 확인했다.
- 목표마다 설명·연습·확인 장이 있고, 학생용에도 확인 장이 남는다.
- 학생용 PPTX와 활동지에 정답이 없다. 정답은 수업용의 피드백 장, 노트, 부모용 안내에만 있다.
- 공식 성취기준 코드는 원문으로 확인한 것만 적는다. 확인하지 않았으면 `standard_code: null`.
- "제작 완료"는 자동 검사와 화면 확인을 통과했다는 뜻이다. 실제 아이에게 수업한 효과는 따로 기록한다.

## 수정과 묶음 제작

- 수정 요청은 영향 범위(내용·평가·표현·디자인)를 찾아 원본에 반영하고 다시 생성한다. 사용자가 PowerPoint에서 직접 고친 파일을 주면 먼저 원본과 차이를 확인해 덮어쓰지 않는다.
- 제목이 바뀌어도 ID는 유지한다. 차시를 나누면 이전 ID와 새 ID의 대응을 남긴다.
- 묶음은 한 단원씩 만든다. 완료한 차시는 다시 만들지 않고, 미완료·변경 차시부터 이어서 한다.

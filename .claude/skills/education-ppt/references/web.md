# 웹 교육 자료 (제작 규칙)

같은 원본(`lessons/*.json`)에서 PPTX와 함께 웹 자료를 만든다. 웹은 아이가 직접 조작하고 반복하는 화면이고, PPTX는 부모가 아이와 함께 보며 시범·비교·대화를 하는 화면이다. 두 형식의 내용과 목적은 달라도 된다. 웹에만 필요한 내용은 장·문항의 `web` 필드에 두고, PPTX 생성은 이 필드를 무시한다.

배경 검토: 브랜치 `claude/intelligent-volta-7k2ms5` 의 `docs/웹전환_검토.md`, `docs/초1_상세검토.md`(2026-11-15, 그 뒤 원본이 많이 바뀌었으므로 숫자는 다시 잰다).

웹 화면의 글도 이 스킬의 다른 규칙을 그대로 따른다: 말투·문장 길이·등장인물(`tone-by-age.md`), 부모 노트와 1:1 진행(`home-tutoring.md`), 정답 자리와 시간(아래 ‘원본 규칙과 맞추기’).

## 정한 것

| 항목 | 내용 |
|---|---|
| 기기 | 기본은 두 기기. 부모 휴대폰(진행, 노트, 정답, 기록) + 아이 태블릿(화면, 조작, 답하기). 아이패드·안드로이드 둘 다 지원한다(iOS Safari, Android Chrome). **기기 한 대 모드도 반드시 둔다**(아래) |
| 배포 | 인터넷 없이 쓸 수 있게 만든다. 한 번 열어 홈 화면에 추가하면 오프라인으로 쓰는 방식(PWA)을 기본으로 하고, 나중에 공개 웹 주소로도 그대로 연다 |
| 두 기기 연결 | 서버 없이 시도하되 실패를 기본으로 가정한다. 물러서는 방식(장 번호 맞추기)이 늘 동작해야 한다(아래) |
| 자동 채점 | 아이 화면에서 한다. 파일에 정답이 들어 있어도 된다(학생용 PPTX의 정답 제거 규칙은 웹에 적용하지 않는다). 중·고생은 소스를 볼 수 있다는 점을 알고 정한 것이다 |
| 그림 | 코드로 직접 그린 단순 아이콘을 쓸 수 있다(아래) |
| 제작 순서 | 초1부터 차례로. 묶음의 내용 보강(검토 보고서의 보강점)을 원본에 반영한 뒤 그 묶음부터 웹으로 만든다 |

## 화면 구성

| 모드 | 내용 | 언제 |
|---|---|---|
| 두 기기 연결 | 부모 휴대폰이 장을 넘기면 아이 화면이 따라가고, 아이 답이 부모 휴대폰에 온다 | 연결에 성공했을 때 |
| 두 기기, 연결 없음 | 아이 화면에 장 번호를 크게 보이고 부모가 휴대폰에서 같은 번호를 누른다. 부모 판정은 부모 휴대폰에만 기록한다 | 연결이 안 되거나 끊겼을 때(기본으로 물러서는 곳) |
| 기기 한 대 | 아이 화면에서 정답·노트·판정 단추를 숨기고, 부모만 여는 ‘부모 화면’(길게 누르기 + 숫자 잠금)으로 본다. 부모 화면이 열려 있는 동안 아이 화면은 가린다 | 태블릿·휴대폰이 한 대뿐일 때 |

- 아이 화면에서 부모 화면·정답·설정으로 넘어가는 길은 잠금 없이 열리지 않게 한다.
- 아이 화면은 가로로 쓴다. 16:9 무대를 쓰면 아이패드(4:3에 가까움)에서는 위아래가 비고 글자가 작아지므로, 학년군 글자 크기 기준을 **4:3 화면에 넣었을 때** 기준으로 잰다.
- 아이가 여럿이면 기기 안에서 아이별로 기록을 나눈다(이름 대신 부모가 정한 별명).
- 다음 차시로 저절로 넘어가거나 끝없이 이어지는 화면을 두지 않는다. 한 회차가 끝나면 멈춘다.
- 연결이 끊기면 아이 화면을 멈추지 않는다. 지금 장을 그대로 두고 “부모님과 장 번호를 맞추세요”를 보인 뒤 ‘연결 없음’ 모드로 넘어간다.

### 두 기기 연결에서 확인할 것

- 브라우저끼리 직접 잇는 방법(WebRTC)도 처음에 연결 정보를 주고받는 단계가 필요하다. 서버가 없으면 두 기기가 서로 QR 코드를 비추어 주고받는다(카메라 권한 → 보안 연결 → PWA가 유리).
- 아이패드는 화면이 꺼지거나 앱을 바꾸면 연결이 끊길 수 있다. 다시 잇는 단계를 짧게 만든다.
- 손으로 주고받는 연결 정보에는 그 순간의 네트워크 주소가 들어 있어, 와이파이가 바뀌거나 기기가 잠들면 다시 짝지어야 한다. 주고받기가 느리면 연결 확인 시간이 지나 실패하기도 한다. 짝짓기는 몇 초 안에 끝나게 만든다.
- 아이패드 홈 화면 앱(PWA)에서 카메라가 멈추거나 권한을 다시 묻는 문제가 보고되어 왔다. QR을 카메라로 못 읽으면 사진을 골라 읽는 방법으로 물러선다.
- 그래서 연결 모드는 ‘되면 좋은 기능’으로 둔다. 모든 수업은 ‘연결 없음’ 모드만으로 끝까지 할 수 있어야 한다.
- 시제품에서 iOS Safari와 Android Chrome으로 실제로 연결해 보기 전에는 ‘연결 모드가 된다’고 적지 않는다.

## 수업 단위: 하루와 이틀

- 원본의 `break_after` 가 하루 분량의 끝이다. `split_default: true` 인 차시(고등 대부분)는 웹에서도 **이틀 차시**로 연다: 첫날은 `break_after` 장까지, 둘째 날은 그다음 장부터.
- 둘째 날은 노트의 ‘둘째 날 시작 질문’을 첫 화면에 보이고, 첫날 내용을 2~3문제로 다시 꺼낸 뒤 이어 간다.
- 하루 중간에 멈추면 다음에 연 곳에서 이어 한다(어느 장·문항까지 했는지 기록).
- 노트의 ‘꼭 할 문제 / 시간이 되면’ 줄을 구조로 옮긴다(`web.priority: "must" | "optional"`). 부모가 ‘시간이 모자라요’를 누르면 남은 장에서 `must` 만 보인다. 문제를 지우지 않는다.
- 남은 시간 막대는 그날 분량(하루 약 20~30분) 기준으로 보인다. 끝나기 2~3분 전 “곧 끝나요”, 끝나면 “다 했어요 → 끄고 제자리에” 화면에서 멈춘다. 20분쯤 눈 쉬기를 안내한다.

## 문항의 `web` 필드

노트 문장에만 있던 정답·허용 답·오답 대응을 구조로 둔다. 연습·확인 장의 문항마다(고르기·견주기 장은 장에):

```json
"web": {
  "id": "q-borrow-13-5",
  "input": "numpad",
  "answer": "8", "accept": ["8", "여덟"],
  "steps": [ { "label": "중간 수", "answer": "10" } ],
  "wrong": [
    { "value": "12", "misconception": "M1", "feedback": "5개 뺐는데 1개만 줄었어요", "goto": "S04" }
  ],
  "priority": "must",
  "say": "열세 개에서 다섯 개를 빼면 몇 개일까요?",
  "lang": "ko"
}
```

| 필드 | 뜻 |
|---|---|
| `id` | 문항의 바뀌지 않는 이름. 장 번호(S05 ①)는 원본을 고치면 바뀌므로 기록·채점 연결에 쓰지 않는다. 한번 정하면 문항을 지울 때까지 바꾸지 않는다 |
| `input` | 아래 ‘입력 종류’ |
| `answer`, `accept` | 정답과 함께 맞음으로 볼 답. 같은 답으로 보는 규칙은 ‘답 맞추기’를 먼저 적용하고, 그 밖의 다른 꼴만 `accept` 에 적는다. 순서가 여럿 맞으면 `order` 의 허용 범위를 적는다(예: 처음과 끝만 고정) |
| `steps` | 중간 단계 칸(중간 수, 가르기 두 칸). 어느 단계에서 틀렸는지 구별한다 |
| `wrong` | 흔한 오답 → 원본 `misconceptions` 의 ID → 아이에게 보일 피드백(정답을 바로 말하지 않고 되묻기) → 돌아갈 장 |
| `priority` | `must`(꼭 할 문제) · `optional`(시간이 되면). 노트의 같은 줄과 맞춘다 |
| `say` | 기계 음성이 읽을 문장. 숫자·시각·단위는 읽는 말로 쓴다(“3시” → “세 시”, “13개” → “열세 개”, “8 − 3” → “팔 빼기 삼”). 고유어/한자어를 정해 쓴다 |
| `lang` | `say` 의 언어(`ko`, `en`). 영어 문장은 `en` 으로 따로 둔다 |

- 아이에게 보이는 글(`feedback`, 지시, 힌트)은 `tone-by-age.md` 를 따른다. 위 예처럼 해요체는 초등까지다. 중·고는 교과서식(설명 ‘~이다’, 물음 ‘~인가?’, 지시 ‘~하시오’)으로 쓴다.
- 말로 답하는 문항(두 가지로 읽기, 까닭 말하기, 소리 내어 읽기)은 `parent`: 아이 화면에는 문제만 보이고, 부모 화면에 ‘맞음 · 도움 · 아직’ 단추가 뜬다. 이 결과가 기록표가 된다.
- 정답이 없는 ‘나라면 어떻게 할까’ 고르기는 `none`: 고른 것을 부모 화면에 보내고, 부모가 ‘까닭 말함 / 도움’을 기록한다. 고른 뒤 표정·소리로 정답을 암시하지 않는다.
- 자동 채점 뒤에도 “어떻게 알았어?”를 묻는다. 계산이 맞아도 까닭을 말하지 못하면 개념 목표는 확인 완료가 아니다(`home-tutoring.md`).
- 자동 채점하는 문항은 정답이 하나로 정해지는지 먼저 확인한다. 여럿이면 `accept` 나 허용 범위를 적고, 정할 수 없으면 `parent` 로 둔다.

## 입력 종류

| `input` | 쓰는 곳 | 채점 |
|---|---|---|
| `numpad` | 수 하나(자연수·소수·음수) | 자동 |
| `expr` | 식·분수·근호·지수·부등식 구간·좌표·순서쌍(중·고 수학, 과학 계산) | 자동. 화면 수식 자판(분수 칸, √, ^, ≤ ≥, 괄호)을 쓰고, 값으로 같은지 비교한다(‘답 맞추기’) |
| `short` | 낱말·짧은 구(용어, 국어·사회 단답, 영어 낱말) | 자동. `accept` 를 넉넉히 적고, 정할 수 없으면 `parent` |
| `choice` · `multi` | 하나 고르기 · 모두 고르기 | 자동 |
| `tap` | 그림에서 누르기 | 자동 |
| `drag` | 끌어 넣기·분류. 끌기가 어려운 아이를 위해 ‘누르고 → 놓을 곳 누르기’도 늘 된다 | 자동 |
| `order` | 순서 맞추기 | 자동(허용 범위) |
| `compose` | 자모·숫자 카드 조립 | 자동 |
| `plot` | 좌표평면에 점·직선·그래프 찍기, 막대·꺾은선 그리기 | 자동(허용 오차를 적는다) |
| `code` | 파이썬 코드 쓰기·고치기(정보 차시) | 아래 ‘코드’ |
| `trace` | 따라 쓰기 | 부모 판정 |
| `write` | 문단 이상의 글(논증문, 비평문, 보고서, 영어 글쓰기) | 부모 판정. 원본의 기준표를 부모 화면에 보인다 |
| `parent` | 말로 답함 | 부모 판정 |
| `none` | 채점 안 함 | — |

- 수·식 입력은 기기 자판을 띄우지 않고 화면 자판을 쓴다(기기 자판이 문제를 가린다). 식 입력은 수식 입력 부품 하나(예: MathLive의 수식 칸·화면 자판)를 정해 쓰고, 학년마다 필요한 단추만 남긴다(초등: 숫자·분수 칸, 중·고: √, 지수, 부등호, 괄호).
- 한글 단답은 글자 조합이 끝난 뒤(조합 끝 이벤트) 채점한다. 조합 중인 글자로 채점하면 ‘가’를 치는 도중 ‘ㄱ’으로 틀림이 난다.

### 답 맞추기 (자동 채점 전에 모든 답에 적용)

- 앞뒤 빈칸, 연속 빈칸, 전각/반각 문자는 무시한다. 한국어 단답의 띄어쓰기는 무시한다(띄어쓰기를 묻는 문항은 `exact: true`).
- 단위: ‘3 cm’, ‘3cm’, ‘3센티미터’를 같게 본다. 단위가 답의 일부인 문항(단위 고르기)은 `exact: true`.
- 수: 같은 값이면 같은 답으로 본다(1/2 = 0.5 = 2/4). 문항이 꼴을 묻는 경우(기약분수로, 소수로, 근호를 써서)는 `form` 에 적는다(`"form": "irreducible"`, `"decimal"`, `"radical"`). 반올림이 있으면 자리를 적는다.
- 식: ‘x = 3’과 ‘3’, ‘y = 2x + 1’과 ‘y = 1 + 2x’를 같게 본다. 구간·부등식은 같은 범위면 같다.
- 영어: 대소문자·끝 문장 부호는 무시한다. 철자를 묻는 문항은 `exact: true`.
- 계산 비교는 원본 `checks` 와 같은 계산기(정확한 분수 계산)를 JS로 옮겨 쓴다.

### 틀렸을 때

- 첫 번째 틀림: `wrong` 에 맞는 오답이면 그 피드백(되묻기), 아니면 일반 되묻기 + 힌트 열기.
- 두 번째 틀림: 원본 노트의 ‘막히면’ 안내를 따라 `goto` 장이나 보충 장으로 보낸다. 보충 뒤 원래 문항으로 돌아온다.
- 세 번째 틀림: 정답을 보여 주지 않고 부모 화면에 ‘도움 필요’를 보낸다. 기록은 ‘도움’이 된다.
- 고르기·견주기 장에서는 틀린 뒤 남은 보기를 차례로 눌러 맞히는 것을 막는다. 두 번째 시도부터는 고르기 전에 까닭을 말하게 하고(부모 판정) 그 뒤에 고른다.
- 틀림 소리·빨간 화면·점수 깎기를 쓰지 않는다. 맞음 표시도 짧게 한다.
- 어떤 경로로 끝나든 그 장을 떠나기 전에 아이가 **맞는 답과 까닭을 한 번은 확인**하게 한다(부모가 설명하거나 정답 장을 함께 본다). 답을 못 떠올린 채 확인 없이 넘어가는 반복 연습은 효과가 없거나 해롭다는 연구가 있다.
- 피드백은 바로 준다(나중에 모아서 주지 않는다). 설명형 피드백(왜 틀렸는지 되묻기)이 평균적으로 더 효과가 크지만 어린 학습자에게는 효과가 작다는 결과도 있으므로, 초1~2는 되묻기를 짧게 하고 시범(그림·조작으로 다시 보이기)으로 바로 잇는다.

## 원본 규칙과 맞추기

- **정답 자리:** 고르기·견주기의 맞는 쪽이 한쪽으로 몰리지 않게 한 원본 규칙(가/나, 왼쪽/오른쪽을 이웃 차시끼리 엇갈리게)을 웹도 지킨다. 웹에서 보기 순서를 섞지 않는다. 섞으면 부모 화면·노트의 ‘정답: 가’와 어긋난다. 섞고 싶으면 부모 화면에 지금 화면의 기호로 정답을 보인다.
- **자동 생성 연습:** 정답 자리와 정답 값이 고르게 퍼지게 만든다(같은 답이 연달아 나오지 않게, 고르기 정답 자리를 고르게).
- **시간·이틀 차시:** 위 ‘수업 단위’를 따른다.
- **말투:** 학년군별 말투를 웹의 모든 아이 화면 글에 적용한다. 따옴표 안의 말, 읽기 지문, 영어는 원본대로 둔다.
- **원본과 같이 고치기:** 원본을 고치면 웹 출력을 다시 만든다. 장 순서·번호가 바뀌면 `goto` 와 문항 `id` 연결을 다시 검사한다.

## 음성

| 구분 | 방법 | 예 |
|---|---|---|
| 기기 음성(TTS) | 기기에 들어 있는 음성으로 그 자리에서 읽는다. 파일이 필요 없다. `say` 와 `lang` 을 쓴다 | 낱말, 지시문, 이야기 읽어 주기, 받아쓰기 불러 주기, 수 읽기, 영어 문장 |
| 음성 파일 | 미리 만들어 함께 배포한다. 같은 목소리·같은 높이로 만든다 | 자모 낱소리([그] [끄] [크]), 받침 끝소리([윽] [은]…), 늘였다 줄이는 이어 읽기([그…아] → [가]), 예사·된·거센 세 짝, 문장 부호 억양 대비, 시 낭독, 목소리 비교 |
| 소리 효과 | 코드로 만든다 | 박(70·90·110 BPM), 손뼉·무릎, 효과음 |

- 기기에 그 언어의 음성이 없을 수 있다(일부 안드로이드, 영어·한국어 중 하나만 깔린 기기). 처음 열 때 음성이 있는지 확인하고, 없으면 소리 단추 대신 “부모님이 읽어 주세요”를 보이고 부모 화면에 읽을 문장을 띄운다.
- 아이패드는 사용자가 누를 때만 소리(기기 음성 포함)를 낸다. 장이 바뀔 때 저절로 읽어 주기를 기대하지 말고, 읽을 거리마다 소리 단추를 두어 아이가 누르게 한다. 첫 화면의 ‘시작’ 단추로 소리 파일 재생을 연다.
- 안드로이드 Chrome의 음성 목록은 기기 제조사·버전마다 다르고 늦게 채워진다. 목록이 다 채워진 뒤(`voiceschanged`) 언어가 `ko`·`en` 으로 시작하는 음성을 찾는다. 아이패드도 OS 버전에 따라 목록이 달라진 사례가 있다.
- 읽는 빠르기를 부모가 바꿀 수 있게 한다(초1은 느리게 시작).
- 기계 음성에 자모 낱자(ㄱ, ㅏ)를 그대로 넣지 않는다(‘기역’으로 읽거나 소리를 내지 않는다). 낱소리는 음성 파일로 한다.
- 음성 파일은 처음 쓰기 전에 부모가 한 번 들어 확인하고, 마음에 들지 않으면 부모 휴대폰에서 직접 녹음해 바꿀 수 있게 한다. 녹음은 그 기기에만 저장한다.
- 소리로 구별하게 하는 문제를 만들지 않는 것: ㅐ/ㅔ, ㅚ/ㅙ/ㅞ, ㅒ/ㅖ(표준 발음에서도 구별이 약하다). 뜻으로 고르게 한다.
- 노트의 발음 표기 [ ]와 기계 음성이 다르게 읽지 않게, 쓴 대로 소리 나지 않는 낱말(참외[차뫼], 열쇠[열쐬])은 한글 단원의 예에서 피한다.
- 소리로만 전하는 내용에는 같은 내용의 글을 함께 보인다(소리를 못 듣는 상황).

## 그림(아이콘)

- 물건 하나·기호 하나를 나타내는 단순 아이콘을 SVG 코드로 직접 그린다. 생성형 이미지와 사진은 쓰지 않는다.
- 아이콘 안에 수량·글자를 넣지 않는다. 수량은 기존 그림(배열, 십 칸 틀, 수 모형)으로 나타낸다.
- 아이콘마다 이름을 붙이고, 같은 이름은 어디서나 같은 아이콘으로 쓴다. 사람 아이콘은 성별·나이가 한쪽으로 치우치지 않게 한다. 중·고 화면에는 어린 느낌의 캐릭터·동물 아이콘을 쓰지 않는다(`tone-by-age.md`).
- 글을 못 읽는 아이가 혼자 할 수 있게, 분류·고르기 문항의 낱말에는 아이콘과 소리 단추를 함께 둔다.

### 대체 설명 두 가지

- 그림마다 대체 설명을 **두 가지**로 둔다. `alt`(아이 화면용)는 정답을 드러내지 않는 설명(“시계 그림”, “상자 모양 물건 세 개”), `alt_full`(부모 화면·화면 읽기용)은 그림을 그대로 말하는 설명(“8시 30분을 가리키는 시계”).
- 화면 읽기 프로그램을 켠 아이에게 그림을 볼 수 없는 만큼의 정보를 줘야 하는 문항(시각 장애)은 `alt_full` 을 쓰되, 그 문항은 자동 채점에서 빼고 `parent` 로 둔다.

## 코드 (정보 차시)

- 파이썬 코드를 쓰는 차시(17개)는 브라우저 안에서 돌리는 파이썬(Pyodide 등)을 쓸 수 있다. 본체만 해도 수 MB이고 꾸러미를 더하면 수십 MB가 되어 오프라인 저장 한도와 첫 내려받기에 부담이 크다. 그래서:
  - 코드 실행이 없어도 수업이 끝까지 되게 만든다(코드와 출력 예측 → 원본에 적힌 실제 출력과 견주기).
  - 실행 기능은 정보 차시를 처음 열 때 부모가 ‘내려받기’를 고른 경우에만 받는다. 꾸러미는 표준 라이브러리 안에서만 쓴다.
- 원본의 예시 코드와 그 출력은 웹에서 실제로 돌려 같은지 검사한다(원본 검토에서 python3로 확인한 값과 같아야 한다).
- 채점은 정해 둔 입력에 대한 출력 비교로 한다. 무한 반복을 막는 시간 제한을 둔다. 네트워크·파일 접근은 막는다.

## 자동으로 만드는 연습

- 연습량이 부족한 내용은 웹이 문제를 만들어 반복한다. 틀린 문제는 간격을 두고 다시 낸다(같은 날 몰아서 하기보다 날을 나누어 다시 내는 것이 효과가 크다). 통과 기준(예: 연속 10문제 중 9개)을 정한다.
- 시간 기준(한 문제 5초 안)은 **정확하게 풀게 된 뒤에만** 쓴다. 시간은 아이에게 보이지 않게 재고(초시계 화면 없음), 점수나 순위로 보이지 않는다. 시간 제한 연습이 불안을 키운다는 주장과 그렇지 않다는 연구가 엇갈리므로, 부모가 끌 수 있게 한다.
- 복습 연습은 이미 배운 여러 유형을 섞어 낸다(섞어 풀기). 유형을 고르는 판단 자체가 배움인 중·고 수학에서 특히 쓴다. 초등에서 섞어 풀기의 근거는 아직 적으므로, 초등은 한 유형을 충분히 익힌 뒤에 섞는다.
- 초1 수학 사실 줄기: 10의 짝 → 10 − □ → 10 + 몇 → 받아올림 36개 → 받아내림 36개.
- 생성기는 원본의 `checks` 와 같은 계산기로 정답을 만든다. 만든 문제의 그림 수량이 정답과 맞는지 검사한다.
- 만든 문제는 그 차시의 범위(`boundary`) 안에 머문다. 아직 안 배운 수의 범위·꼴·낱말을 쓰지 않는다.
- 생성은 고정값(seed)으로 다시 만들 수 있게 하고, 검사에서 seed 몇 개로 만든 문제를 모두 검산한다.

## 화면으로 대신하지 않는 것

- 실물 조작(바둑돌·콩 묶기·저울·물 붓기), 몸 활동(달리기·박·손 씻기), 실제 관찰(하늘·생물), 만들기·그리기, 역할극과 대화, 그림일기, 실험.
- 이런 장은 웹에서 ‘짧은 안내 + 다 했어요’로 두고, 결과는 부모 화면의 기록표에 남긴다. 화면 속 놀이로 같은 활동을 대신하지 않는다.
- 관찰·실험 차시는 아이가 관찰을 마치기 전에 결과 화면이 열리지 않게 잠근다. 원본의 예시 결과는 ‘예시’로 표시한 채 부모가 열 때만 보인다.
- 활동지는 종이로 유지한다. 손으로 쓰는 연습은 종이가 낫다.

## 민감한 주제

대상: 신체 경계·낯선 사람·학대 신고, 성 건강·동의, 정신 건강·자해 위험, 중독, 폭력·괴롭힘, 개인 정보(원본 35차시 안팎, 내용으로 찾아 표시한다).

- 점수·별·‘틀렸어요’ 소리가 있는 게임으로 만들지 않는다. 자동 채점 대신 대화(`parent`)로 한다.
- 아이가 자기 경험·감정·가족 이야기를 적는 칸의 내용은 기기에 남기지 않는다. 남겨야 하면 ‘했음’ 표시만 기록한다.
- 도움 기관 번호는 원본과 같게 보인다(112, 117, 119, 109, 1388). 1388은 휴대전화로 걸 때 지역 번호를 함께 누른다(여성가족부 안내: ‘휴대전화: 지역번호+1388’). 전화가 어려운 청소년을 위해 문자(1388로 보내기)·카카오톡 ‘청소년상담1388’ 채널·누리집(www.1388.go.kr)도 함께 적는다. 화면에는 바깥 링크를 걸지 않고 글로만 적는다.
- 이런 장의 기록은 부모 화면에만 보인다. 다른 가족이 같은 기기를 쓸 수 있다는 점을 생각한다.

## 접근성

- 글자 크기는 학년군 기준(`style.js`)보다 작게 하지 않고, 부모가 한 단계 크게 할 수 있다. 화면 확대를 막지 않는다.
- 글자와 배경의 명도 대비는 본문 4.5:1 이상. 색만으로 구별하지 않는다(정답·틀림, 분류 바구니, 그래프 계열에 모양·글자를 함께).
- 누르는 곳은 44×44 px 이상(WCAG 2.2의 최소 기준은 24×24 px, 권장 기준이 44×44 px이며 어린 아이에게는 권장 기준을 쓴다). 끌기는 ‘누르고 놓기’로도 된다(WCAG 2.2 끌기 동작 기준). 시간 제한이 있는 연습은 부모가 끌 수 있다.
- 국내 기준인 한국형 웹 콘텐츠 접근성 지침(KWCAG 2.2, 검사 항목 33개)을 검사 목록으로 쓴다.
- 움직임 줄이기 설정을 따르고, 깜박이는 효과를 쓰지 않는다.
- 왼손잡이를 위해 따라 쓰기 시범과 끌기 손잡이의 방향을 바꿀 수 있다.

## 기록과 개인 정보

- 아이가 이름·주소·사진을 넣는 칸을 두지 않는다. 아이 이름은 부모 화면에서만 쓴다.
- 바깥 링크·광고·채팅·결제가 없다. **글꼴·라이브러리·아이콘을 외부 서버(CDN, 글꼴 서비스)에서 불러오지 않는다.** 모두 함께 싣는다(오프라인에서 깨지지 않게, 아이 기기 정보가 밖으로 나가지 않게). 이용 통계 도구도 넣지 않는다.
- 기록은 기기 안에만 저장한다. 공개 웹이 되어도 아이 정보를 밖으로 보내지 않는다.
- 기록이 지워지지 않게 **열 때마다** 브라우저에 영구 저장을 요청한다(`navigator.storage.persist()`. 아이패드는 홈 화면 앱인지 등을 보고 허락하므로 한 번 허락이 계속된다고 가정하지 않는다).
- 아이패드는 Safari 탭으로 연 페이지에 쓴 기록을 쓰지 않고 7일이 지나면 지울 수 있고, 홈 화면 앱과 Safari 탭은 저장 공간을 나누어 쓰지 않는다. 그래서 **홈 화면에 추가한 뒤에 수업을 시작**하게 안내하고, 탭으로 열렸으면 첫 화면에서 알린다.
- 홈 화면 앱에서도 기록이 지워졌다는 보고가 있으므로, 부모 화면에 ‘기록 내려받기’(파일)와 ‘기록표 인쇄’를 둔다. 기기를 바꿀 때 파일로 옮긴다.
- 오프라인 저장은 학년 단위로 부모가 고른다(1,316차시와 음성 파일을 한 번에 받지 않는다). 남은 저장 공간을 부모 화면에 보인다.
- 기록은 원본의 목표(A, B …)와 기록표(`worksheet.record`)에 맞춰 보인다. 부모가 차시마다 ‘목표 확인 완료 / 도움 / 아직’을 볼 수 있게 한다.
- 아이 화면에 늘 ‘어른 불러요’ 단추를 둔다(두 기기가 연결되어 있으면 부모 휴대폰에 알림, 아니면 소리).

## 자료를 고칠 때(판과 기록)

- 웹 출력에 차시마다 판 번호(원본 내용의 해시)를 넣는다. 오프라인 앱은 다시 인터넷에 연결되었을 때 새 판을 받고, 수업 중에는 바꾸지 않는다(다음에 열 때 바뀜).
- 기록은 문항 `id` 와 차시 판으로 남긴다. 판이 바뀌어도 같은 `id` 의 기록은 이어지고, 없어진 문항의 기록은 ‘지난 판’으로 남긴다.

## 공개 웹으로 바꾸기 전에

- 읽기 지문·작품 인용·그림·글꼴·아이콘·음성 파일의 사용 조건을 확인한다.
  - 저작권법의 수업 목적 이용(제25조)은 학교·교육기관의 수업에 대한 것이고, 가정 안 복제(제30조 사적 이용)도 공개 웹 게시까지 덮지 않는다. 공개 웹에는 **보호기간이 끝난 작품(저작자 사망 다음 해부터 70년)이거나 허락을 받은 것, 직접 지은 글**만 싣는다. 보호기간이 끝난 작품은 한국저작권위원회 ‘공유마당’에서 확인할 수 있다.
  - 지금 국어 지문은 보호기간이 끝난 작품(현진건 「운수 좋은 날」, 김유정 「동백꽃」, 김소월 「진달래꽃」, 한용운 「님의 침묵」, 이효석 「낙엽을 태우면서」 등)과 지어낸 글이다. 새 지문을 넣을 때마다 확인한다.
  - 글꼴은 웹에 함께 실을 수 있는 것만 쓴다. Pretendard와 Noto Sans KR은 SIL Open Font License라 함께 실을 수 있다. 쓰는 글자만 남겨(subset) 크기를 줄인다.
- 만 14세 미만 아동의 개인정보를 처리하려면 법정대리인의 동의를 받고 확인해야 한다(개인정보 보호법 제22조의2). 지금 설계는 아이 정보를 기기 밖으로 보내지 않아 이 처리가 생기지 않는다. 기록을 서버로 옮기거나 계정을 만드는 기능을 넣는다면 그 전에 이 조항과 아동용 고지(쉬운 말)를 따로 검토한다. AI 디지털교과서를 둘러싸고 학습 데이터 수집이 쟁점이 된 만큼, 학습 기록을 밖으로 보내지 않는 원칙을 공개 문서에 밝힌다.

## 검사

- 장마다 고정 16:9 무대에서 글 넘침을 브라우저에서 실제로 잰다.
- `web` 필드: 정답이 원본 `checks`·노트와 같은지, `wrong` 의 오개념 ID가 원본에 있는지, `goto` 장이 있는지, `id` 가 차시 안에서 겹치지 않는지, `priority` 가 노트의 ‘꼭 할 문제’ 줄과 맞는지.
- 답 맞추기: 문항마다 `answer` 와 `accept` 가 실제로 맞음으로 판정되는지, 흔한 오답이 맞음으로 판정되지 않는지 자동으로 돌려 본다.
- 아이 화면에 정답이 미리 보이지 않는지(그림 `alt`, 캡션, 칸 수, 보기 순서).
- 정답 자리: 차시와 이웃 차시의 고르기·견주기 정답 분포를 센다.
- 말투: 아이 화면 글이 학년군 말투를 지키는지(원본 검사와 같은 방식).
- 접근성: 자동 검사 도구(axe 등)와 대비 검사를 돌린다.
- 오프라인: 비행기 모드에서 처음부터 끝까지 한 차시를 한다(소리·그림·코드 실행 포함).
- 기록 보존: 기록을 남기고 일주일 뒤 같은 기기에서 남아 있는지 본다. 판을 바꾼 뒤에도 이어지는지 본다.
- 성능: 오래된 저사양 태블릿(안드로이드 보급형, 몇 세대 전 아이패드)에서 장 넘김·조작이 늦지 않은지 본다.
- 화면 비율: 16:9 무대를 4:3 아이패드 화면에 넣었을 때 학년군 글자 크기 기준을 지키는지 잰다.
- 한글 입력: 아이패드·안드로이드 기본 한글 자판으로 단답을 쳐서 조합 중에 틀림이 나지 않는지 본다.
- 소리: 기기 음성이 없는 상태(음성 삭제·다른 언어만 설치)에서 ‘부모님이 읽어 주세요’로 물러서는지 본다.
- 아이패드 Safari와 안드로이드 Chrome에서 열어 조작·소리·기록 보존을 확인한다. 확인하지 못한 기기는 통과로 적지 않는다.
